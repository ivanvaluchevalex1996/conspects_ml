## 2.2 Линейные модели

### **Что не следует путать**

**dL/dz — градиент loss по логитам (домашка)**

Одна фраза: dL/dz — это 10 чисел: «как loss меняется, если крутить каждый logit по отдельности».

---

**Что такое dL/dz**

```
L  — loss (одно число, «насколько плохо»)
z  — логиты (10 чисел: z0, z1, ... z9)
```

**dL/dz** — не одна формула, а сокращение:

> как loss меняется, если крутить каждый logit по отдельности

То есть **10 частных производных** в одном векторе:

```
dL/dz = [ dL/dz0, dL/dz1, dL/dz2, ... dL/dz9 ]
          ↑         ↑
       grad[0]   grad[1]   ...   = dprediction
```

**Градиент** = все эти `dL/dz_k` вместе.

В коде домашки это `dprediction` — массив той же формы, что логиты `(10,)` или `(batch, 10)`.

---

**Где конкретная формула**

Сама запись **dL/dz** — только имя: «градиент loss по логитам».

**Числа внутри** даёт формула из кода (после softmax + cross-entropy):

```
dL/dz_k = grad[k] = probs[k] - one_hot[k]
```

Словами:

- `probs[k]` — вероятность класса k после softmax
- `one_hot[k]` — 1, если k правильная цифра; 0, если нет

Пример. Правильный класс = 1, после softmax:

```
probs    = [0.02, 0.81, 0.04, ...]
one_hot  = [0,    1,    0,    ...]

dL/dz    = [0.02, -0.19, 0.04, ...]
```

У правильного класса градиент **отрицательный** — loss хочет поднять этот logit (уменьшить loss).

---

**Связь с конспектом**

В конспекте для **2 классов** (один logit, сигмоида):

```
dL/dz = p - y
```

Там `z` один → **dL/dz** одно число.

У тебя **10 классов** → `z` из 10 чисел → **dL/dz** — вектор из 10 чисел. Та же идея, только размерность больше.

Файлы:

- `Упрощенное пояснение линейной классификации с примером.md` — градиент Log Loss: `dL/dw = -x * (y - p)`
- `Линейные модели.md` — Log Loss, softmax в домашке

Здесь мы считаем не `dL/dw` (по весам), а **dL/dz** (по логитам) — промежуточный шаг перед весами.

---

**Аналогия с параболой**

```
y = x²   →   y' = 2x        ← одна переменная, одна производная

loss(z)  →   dL/dz = [...]  ← 10 переменных, 10 частных производных
```

Одна переменная — одна производная.
Десять логитов — десять частных производных в одном векторе.

---

**Цепочка в домашке**

```
логиты z
   ↓ softmax
probs
   ↓ cross-entropy + train_y
loss L (одно число)
   ↓
dL/dz = probs - one_hot     ← dprediction, форма как у z
   ↓ (потом через X)
dL/dW
```

Функция `softmax_with_cross_entropy` как раз возвращает **loss** и **dL/dz** (`dprediction`).

---

**Итог**

| Что | Смысл |
|----|----|
| **dL/dz** | имя градиента: производные loss по каждому logit |
| **Формула** | `probs[k] - one_hot[k]` для каждого k |
| **В коде** | `dprediction`, тот же размер, что `predictions` (логиты) |
| **Зачем** | сказать градиентному спуску, как подкрутить z (и потом W) |

**dL/dz** — имя.

**probs - one_hot** — что подставлять в числа.

Функция потерь: общее и конкретное

1. Функция потерь — это общее понятие

Да. Функция потерь — это любая функция, которая возвращает число, показывающее, насколько плохо модель предсказывает. По этому числу мы считаем градиент и обновляем веса.

**Примеры:**

- **MSE** (для регрессии)
- **MAE** (для регрессии)
- **Перцептрон loss** (для классификации)
- **Hinge loss** (для классификации)
- **Log loss / кросс-энтропия** (для классификации с вероятностями)

Все они — виды функции потерь.

---

2. Кросс-энтропия — это конкретная функция потерь

Да. Она используется в классификации, когда модель предсказывает вероятности (через сигмоиду или softmax).

- **Бинарная кросс-энтропия** — для двух классов (логистическая регрессия).
- **Категориальная кросс-энтропия** — для многих классов (softmax).

Она не «отдельная сущность», а один из видов loss.

---

3. Аналогия с фруктами — отличная!

| Общее | Конкретное |
|:---|:---|
| Фрукт | Яблоко, груша, банан |
| Функция потерь | MSE, кросс-энтропия, hinge, перцептрон |

Всё верно. Кросс-энтропия — это как «яблоко» среди фруктов.

---

4. Что НЕ является функцией потерь

Вы абсолютно правы:

- **Сигмоида** — не loss, это функция активации, превращает логит в вероятность.
- **Softmax** — не loss, это активация для многоклассовой классификации.

Они преобразуют логиты в вероятности, а функция потерь (кросс-энтропия) уже считает ошибку между этими вероятностями и правильным ответом.

---

5. Цепочка, которую вы написали — идеальна

> Логит → сигмоида/softmax → вероятности → кросс-энтропия (это и есть loss)

Да, именно так:

1. Логит $z = \langle w, x \rangle$
2. Активация (сигмоида или softmax) даёт вероятности $p$
3. Кросс-энтропия считает $-\log(p_{\text{true}})$ и возвращает число — loss
4. По этому loss вычисляется градиент и обновляются веса

---

6. Итог одной фразой

> **Кросс-энтропия = функция потерь. Но не любая функция потерь = кросс-энтропия.**

Полный поток в домашке

Твоя цепочка — правильная

Для одной картинки:

1. **Линейная модель → логиты**

   Пиксели $\times$ веса (отдельный столбец весов на каждый класс) → 10 чисел: $z_0, z_1, \dots, z_9$
2. **Softmax → вероятности**

   «С вероятностью 70% это 3, с вероятностью 5% это 7…» — сумма = 1
3. **Кросс-энтропия → loss**

   Смотрим на правильный класс из данных (например, $y = 3$) и штрафуем: $L = -\log(p_3)$. Чем меньше вероятность у правильного класса, тем больше ошибка
4. **Градиентный спуск → подкрутить веса**

   Считаем градиент loss по весам $W$ и делаем шаг: $W = W - \text{learning_rate} \cdot \text{градиент}$. Повторяем на батчах, много эпох

---

|:---|:---|

| `softmax_with_cross_entropy` | loss + градиент по логитам (удобнее вместе) |
| `linear_softmax` | $X \cdot W$ → логиты → loss + градиент по $W$ |
| `l2_regularization` | штраф за большие веса (из конспекта Ridge) |
| `LinearSoftmaxClassifier.fit` | SGD: батчи, обновление $W$ |

Перед обучением ещё `check_gradient` — проверка, что градиент посчитан верно.

На тесте softmax снова, но loss не нужен — берёшь класс с $\max$ вероятностью и сравниваешь с правильным ответом (accuracy).

### Введение

Линейные модели — это модели, которые являются линейными по численным признакам объектов. Они используются для решения задач регрессии (предсказание непрерывного значения) и классификации (отнесение к одному из классов).

**__Основная идея__**

Основная идея: представить зависимость между признаками объекта $x = (x_1, \dots, x_D)$ и целевой переменной $y$ в виде взвешенной суммы:

$$
y = w_1 x_1 + \cdots + w_D x_D + w_0
$$

где:

- $y$ — целевая переменная (таргет);
- $(x_1, \dots, x_D)$ — вектор признаков объекта;
- $w_1, \dots, w_D$ — параметры модели (веса).
- $w_0$ — сдвиг;

  [Что такое W0  (сдвиг/bias)? Почему он нужен? Что будет, если его убрать?](https://ivan-valuchev.yonote.ru/doc/chto-takoe-w0-sdvigbias-pochemu-on-nuzhen-chto-budet-esli-ego-ubrat-OH0fd5wint)


[Что означают веса Wi с точки зрения влияния на результат?](https://ivan-valuchev.yonote.ru/doc/chto-oznachayut-vesa-wi-s-tochki-zreniya-vliyaniya-na-rezultat-oILnXSFON6)

[Важность в контексте весов](https://ivan-valuchev.yonote.ru/doc/vazhnost-v-kontekste-vesov-Hg5pZ90m3B)

Более компактно, с использованием скалярного произведения:

$$
y = \langle x, w \rangle + w_0
$$

**__Что это значит на практике? (пример)__**

Представьте, что вы хотите предсказать цену квартиры. У вас есть два признака:

- $x_1$ — площадь квартиры (в м²);
- $x_2$ — количество комнат.

Тогда линейная модель будет выглядеть так:

$$
y = w_1 \cdot x_1 + w_2 \cdot x_2 + w_0
$$

Где:

- $w_1$ — цена за 1 м² (например, 150 000 руб/м²);
- $w_2$ — добавка за каждую комнату (например, 500 000 руб за комнату);
- $w_0$ — базовая цена (например, 1 000 000 руб).

Если квартира имеет площадь 50 м² и 2 комнаты, то предсказание:

$$
y = 150\,000 \cdot 50 + 500\,000 \cdot 2 + 1\,000\,000 = 7\,500\,000 + 1\,000\,000 + 1\,000\,000 = 9\,500\,000
$$

Модель предсказывает цену 9,5 млн рублей.

**__Компактная форма__**

Запись $y = \langle x, w \rangle + w_0$ — это просто короткая форма той же самой формулы.

$$
\langle x, w \rangle = w_1 x_1 + w_2 x_2 + \cdots + w_D x_D
$$

Она удобна, когда признаков много (например, сотни или тысячи), чтобы не писать длинную сумму каждый раз.

**__Преимущества линейных моделей__**

__Простота и интерпретируемость__

Веса $w_i$ показывают вклад каждого признака в предсказание. Знак веса указывает на направление влияния, а его абсолютное значение — на важность признака.

**Пример:** В модели цены квартиры вес $w_1 = 150\,000$ означает: каждый дополнительный м² площади увеличивает цену на 150 000 рублей. Это легко объяснить любому человеку.

__Прозрачность__

Легко объяснить, как модель принимает решения, что критически важно в некоторых областях (например, медицина, финансы).

**Пример:** Врач может объяснить пациенту, почему модель предсказала высокий риск заболевания: «У вас повышен уровень сахара, и это увеличило риск на 20%». В отличие от сложных нейросетей, где это объяснить невозможно.

**__Недостатки__**

__Ограниченность__

Являются узким классом функций и могут не справляться со сложными нелинейными зависимостями.

**Пример:** Цена квартиры может расти быстрее при увеличении площади (эффект масштаба). Но линейная модель всегда добавляет одну и ту же сумму за каждый м² — она не может уловить, что при больших площадях цена за м² растёт. 


Для этого нужно добавлять искусственные признаки (квадрат площади и т.п.) — это называется **feature engineering**.


[feature engineering примеры](https://ivan-valuchev.yonote.ru/doc/feature-engineering-primery-yOATBpgnrx)


__Чувствительность к данным__

Веса могут терять смысл при мультиколлинеарности — приближённой линейной зависимости между признаками.

**Пример:** Если у вас есть два признака: площадь в м² и площадь в сотках (1 сотка = 100 м²). Они жёстко связаны: если известна площадь в м², площадь в сотках вычисляется автоматически. Модель не может понять, какой из этих признаков «настоящий». Веса становятся нестабильными, теряют смысл, и интерпретация становится невозможной.

**Как бороться:**

- Удалять один из зависимых признаков.
- Использовать регуляризацию (об этом дальше в конспекте).


[Проблема и решение мультиколлинеарности](https://ivan-valuchev.yonote.ru/doc/problema-i-reshenie-multikollinearnosti-pzd0se7YTx)

**__Итог__**

Линейные модели — это простой и понятный способ предсказывать значения: взвешенная сумма признаков. Они легко интерпретируются, но ограничены в сложности и чувствительны к данным. Всё дальнейшее в конспекте (MSE, градиентный спуск, регуляризация, классификация) — это способы настроить эту модель, улучшить её и расширить область применения.

**Саммари**

**Главная мысль:**

Линейная модель — это взвешенная сумма признаков. Она простая, понятная и прозрачная, но имеет ограничения.

Что вы должны запомнить:

| Что | Как это работает |
|:---|:---|
| **Формула** | $y = w_1 x_1 + \cdots + w_D x_D + w_0$ — это взвешенная сумма признаков |
| **Веса** | $w_i$ показывают, насколько каждый признак влияет на ответ |
| **Сдвиг** | $w_0$ — это базовое значение (когда все признаки равны нулю) |

Плюсы:

- ✅ Веса легко интерпретировать (каждый признак даёт свой вклад).
- ✅ Модель прозрачна (можно объяснить решение).

Минусы:

- ❌ Не работает со сложными зависимостями (нужно добавлять искусственные признаки).
- ❌ Чувствительна к мультиколлинеарности (зависимости между признаками).

**Вывод:** Линейная модель — это отправная точка в ML. Она хороша, когда нужно быстро получить интерпретируемое решение, но для сложных задач её возможностей может не хватить.


**📌 Пример, где модель «глупая» (нелинейность)**

А теперь представьте, что при площади **100 м²** цена за м² падает до 130 000, потому что большие квартиры сложнее продать.

Линейная модель этого не знает. Она посчитает:

- 150 000 × 100 = 15 000 000 (вместо реальных 13 000 000)
- Ошибка = 2 000 000 рублей.

**Вывод:** линейная модель хороша для простых зависимостей, но не улавливает «хитрости».

### Работа с категориальными признаками

Линейные модели работают только с числовыми признаками. Категориальные признаки необходимо кодировать.

**One-hot-кодирование:** Каждому уникальному значению категориального признака ставится в соответствие новый бинарный признак (принимает значения $0$ или $1$). Единица ставится только для значения, которое принимает объект.

**Проблема и решение:** При использовании one-hot-кодирования возникает линейная зависимость между новыми признаками (их сумма всегда равна 1). Это приводит к неединственности решения и проблемам с интерпретацией. Чтобы избежать этого, один из полученных признаков (базовый) удаляют.


**__Просто помните правило:__**

> Если один признак можно выразить через другие (или их сумму), значит, они зависимы. Это приведёт к проблемам. Нужно убрать лишний признак.

Для one-hot: **всегда удаляйте один столбец** после кодирования. Это стандартная практика, которая устраняет зависимость.


**__Интуиция__**

Представьте, что вы учите модель предсказывать цену дома. У вас есть два признака:

- площадь_в_кв_м
- площадь_в_сотках

   (1 сотка = 100 кв. м)

Эти признаки **жёстко связаны**: второе = первое / 100. Если модель попытается понять, какой из них влияет на цену, она запутается: можно увеличить вес одного и уменьшить вес другого так, что предсказание не изменится. Модель не сможет сказать, какой признак «настоящий».


**__Проблема мультиколлинеарности на примере one‑hot кодирования__**

[Более подробное пояснение примера](https://ivan-valuchev.yonote.ru/doc/bolee-podrobnoe-poyasnenie-primera-0X2zsQH2QQ)

Представьте: мы предсказываем вес питомца по его типу. Есть 3 типа: кот, собака, попугай. Закодируем их one‑hot **без удаления** столбца:

| Объект | type_cat | type_dog | type_parrot | Вес ($y$) |
|:---|:---|:---|:---|:---|
| 1 | 1 | 0 | 0 | 5 |
| 2 | 0 | 1 | 0 | 7 |
| 3 | 0 | 0 | 1 | 3 |

**Модель:**

$$
y = w_0 + w_c \cdot \text{cat} + w_d \cdot \text{dog} + w_p \cdot \text{parrot}
$$

Подставляем данные:

- Объект 1: $5 = w_0 + w_c$
- Объект 2: $7 = w_0 + w_d$
- Объект 3: $3 = w_0 + w_p$

У нас 4 неизвестных ($w_0, w_c, w_d, w_p$) и только 3 уравнения. Решений бесконечно много.

Например, $w_0 = 0, w_c = 5, w_d = 7, w_p = 3$ даёт верные предсказания. Но и $w_0 = 100, w_c = -95, w_d = -93, w_p = -97$ тоже даёт те же предсказания!

Проверка для кота: $100 - 95 = 5$ — верно. Для собаки: $100 - 93 = 7$ — верно.

Почему это плохо?

- **Неединственность** – нельзя сказать, какой набор весов «правильный».
- **Градиентный спуск** будет «метаться» между этими решениями, обучение затягивается.
- **Матрица признаков** становится вырожденной (её нельзя обратить), поэтому аналитическое решение $w = (X^T X)^{-1} X^T y$ не работает.

[Формула нормального уравнения для линейной регрессии с MSE с примером](https://ivan-valuchev.yonote.ru/doc/formula-normalnogo-uravneniya-dlya-linejnoj-regressii-s-mse-s-primerom-r5s3L6lyB2)


Что делаем?

Удаляем один столбец, например, `type_parrot`. Тогда модель:

$$
y = w_0' + w_c' \cdot \text{cat} + w_d' \cdot \text{dog}
$$

Теперь неизвестных 3, уравнений 3 – решение единственное.

Подставляем данные:

- Кот: $5 = w_0' + w_c'$
- Собака: $7 = w_0' + w_d'$
- Попугай: $3 = w_0'$ (потому что оба признака = 0)

Отсюда легко найти: $w_0' = 3$, $w_c' = 2$, $w_d' = 4$.

**Веса имеют чёткий смысл:** базовый вес попугая = 3, кот тяжелее на 2, собака на 4.


__Итоговая модель__

Мы удалили столбец parrot и получили:

$$
\text{Вес} = 3 + 2 \cdot \text{cat} + 4 \cdot \text{dog}
$$

Где:

- $\text{cat} = 1$, если животное — кот, иначе $0$.
- $\text{dog} = 1$, если животное — собака, иначе $0$.

__Как модель делает предсказания для новых данных?__

Теперь, когда к нам приходит новое животное, мы просто смотрим на его тип и подставляем в формулу.

**Пример 1: Пришёл кот**

- Кот: $\text{cat} = 1$, $\text{dog} = 0$
- Считаем: $\hat{y} = 3 + 2 \cdot 1 + 4 \cdot 0 = 5$

Модель предсказывает вес 5 кг. ✅ Правильно!

**Пример 2: Пришла собака**

- Собака: $\text{cat} = 0$, $\text{dog} = 1$
- Считаем: $\hat{y} = 3 + 2 \cdot 0 + 4 \cdot 1 = 7$

Модель предсказывает вес 7 кг. ✅

**Пример 3: Пришёл попугай**

- Попугай: $\text{cat} = 0$, $\text{dog} = 0$
- Считаем: $\hat{y} = 3 + 0 + 0 = 3$

Модель предсказывает вес 3 кг. ✅


__Итог__

Удаление одного столбца убирает неоднозначность, делает обучение устойчивым и веса интерпретируемыми.


**Саммари**

**Главная мысль:**

Категориальные признаки нужно превращать в числа. One-hot-кодирование — самый простой способ, но нельзя оставлять все столбцы — один нужно удалить.

Что вы должны запомнить:

| Шаг | Что делаем |
|:---|:---|
| 1 | Берём категориальный признак (например, тип животного: кот, собака, попугай) |
| 2 | Создаём отдельный столбец для каждой категории (one-hot) |
| 3 | В каждом столбце ставим 1, если объект принадлежит этой категории, иначе 0 |
| 4 | Удаляем один из столбцов (например, столбец "попугай") |

Почему нужно удалять один столбец?

| Проблема | Объяснение |
|:---|:---|
| **Линейная зависимость** | Сумма всех one-hot-столбцов = 1 (для каждого объекта) |
| **Неединственность решения** | Веса можно менять, предсказание не изменится |
| **Обучение страдает** | Градиентный спуск "метается", аналитическое решение не работает |

Что даёт удаление?

- ✅ Столбцы становятся независимыми.
- ✅ Решение становится единственным.
- ✅ Веса становятся интерпретируемыми.

### Линейная регрессия и метод наименьших квадратов (МНК)

**Зачем это нужно?**
Мы хотим предсказывать числа: цену квартиры, рост человека, температуру завтра. У нас есть данные — набор объектов (домов, людей, дней) с числовыми признаками (площадь, возраст, давление) и известными ответами (цена, рост, температура). Линейная регрессия — это самый простой способ найти зависимость между признаками и ответом.

---

#### Постановка задачи

Пусть дан датасет $(X, y)$:

- $y = (y_i)_{i=1}^{N} \in \mathbb{R}^N$ — вектор целевых значений (то, что мы хотим предсказать);

  $y$ — это просто столбик с ответами (ценами).

  Запись $(y_i)_{i=1}^N$ говорит: «Возьми числа от $1$ до $N$ (от первого до последнего) и назови их $y_1, y_2, \dots, y_N$».

  $y \in \mathbb{R}^N$ — означает, что этот столбик живет в $N$-мерном пространстве. Если у нас 3 квартиры, это просто вектор из 3 чисел. Не пугайся слова «пространство» — это просто способ сказать, что у нас есть 3 ответа.
- $X = (x_i)_{i=1}^{N} \in \mathbb{R}^{N \times D}, x_i \in \mathbb{R}^D$ — матрица «объекты–признаки», где каждая строка $x_i$ — это набор признаков $i$-го объекта (например, площадь, число комнат, этаж).

    $X$ — это наша таблица.

    Запись $X \in \mathbb{R}^{N \times D}$ означает, что в таблице $N$ строк (объекты) и $D$ столбцов (признаки).

    $x_i \in \mathbb{R}^D$ — это одна строка из этой таблицы (один объект). В ней $D$ чисел (признаков).      

    Например, для первой квартиры это вектор $(50, 2)$.

**Пример:**

У нас 3 квартиры.

$X = \begin{pmatrix} 50 & 2 \ 70 & 3 \ 90 & 4 \end{pmatrix}$ — площадь и число комнат.

$y = \begin{pmatrix} 5.0 \ 6.5 \ 8.0 \end{pmatrix}$ — цены в млн руб.

Мы ищем функцию $f_w(x_i) = \langle w, x_i \rangle$, где $w$ — вектор весов. 

> Чтобы не таскать свободный член $w_0$, мы добавляем к каждому объекту дополнительный признак, равный $1$. 

[Пояснение](https://ivan-valuchev.yonote.ru/doc/poyasnenie-7UUWwD9MGg)

Тогда $w = (w_0, w_1, \dots, w_D)$ и $x_i = (1, x_{i1}, \dots, x_{iD})$. Теперь $f_w(x_i) = \langle w, x_i \rangle$ автоматически включает свободный член.

---

#### Сведение к задаче оптимизации

Мы хотим, чтобы модель ошибалась как можно меньше. Ошибка измеряется **функцией потерь**. Для регрессии стандартный выбор — **среднеквадратичная ошибка (MSE)**:

$$
MSE(f, X, y) = \frac{1}{N} \|y - Xw\|_2^2 = \frac{1}{N} \sum_{i=1}^{N} (y_i - \langle x_i, w \rangle)^2
$$

**Почему квадрат?**

- Квадрат «наказывает» большие ошибки сильнее, чем маленькие, — модель старается избегать грубых промахов.
- С математической точки зрения квадратичная функция гладкая и выпуклая, её легко минимизировать.

**Зачем делить на** $N$**?**

Чтобы ошибка не зависела от размера выборки. На 100 объектах сумма ошибок будет больше, чем на 10, а средняя — сопоставима.

Задача: найти такие веса $w$, чтобы ошибка была минимальной:

$$
\|y - Xw\|_{2}^{2} \longrightarrow \min_{w}
$$

---

#### Точное аналитическое решение

**Геометрический смысл**

Столбцы матрицы $X$ — это векторы признаков в $N$-мерном пространстве объектов. Вектор $Xw$ — это линейная комбинация столбцов, то есть точка в подпространстве, натянутом на признаки. Мы хотим приблизить вектор $y$ точкой из этого подпространства. Ближайшая точка — это проекция $y$ на подпространство. Условие проекции: вектор ошибки $y - Xw$ перпендикулярен всем столбцам $X$, то есть

$$
X^T (y - Xw) = 0
$$

Отсюда получаем уравнение:

$$
X^T X w = X^T y
$$

Если матрица $X^T X$ обратима, то

$$
\boxed{w = (X^T X)^{-1} X^T y}
$$

**Пример (продолжение):**
Для квартир $X$ — матрица 3×3 (с добавленным столбцом единиц). Подставив данные, мы получим конкретные веса, например $w_0 = 1.0$ млн, $w_1 = 0.08$ млн/м², $w_2 = 0.5$ млн/комнату. Тогда предсказание для квартиры 50 м², 2 комнаты: $1.0 + 0.08\cdot50 + 0.5\cdot2 = 1.0 + 4.0 + 1.0 = 6.0$ млн.

---

**Проблемы точного решения**

1. **Вычислительная сложность** — $O(D^2N + D^3)$. Если признаков $D$ много (сотни тысяч), перемножать и обращать матрицу $X^T X$ очень дорого. Для больших данных этот метод не подходит.
2. **Численная неустойчивость** — если признаки почти линейно зависимы (мультиколлинеарность), матрица $X^T X$ плохо обусловлена (близка к вырожденной). Тогда небольшие ошибки в данных приводят к огромным изменениям весов. Например, если у нас есть два признака: площадь в м² и площадь в сотках (1 сотка = 100 м²), они почти идеально коррелируют. Формула даст огромные по модулю веса, которые будут компенсировать друг друга, но при малейшем шуме они «слетят».

---

#### Улучшение численных свойств решения

Чтобы избежать проблем с обращением $X^T X$, используют более устойчивые разложения матрицы $X$.

**1. QR-разложение**

Любую матрицу $X$ можно представить как $X = QR$, где $Q$ — ортогональная матрица (столбцы перпендикулярны и единичной длины), а $R$ — верхнетреугольная. Тогда формула для весов упрощается:

$$
w = R^{-1} Q^T y
$$

Обращать верхнетреугольную матрицу $R$ легко и устойчиво. Ошибка зависит от числа обусловленности $X$, а не от его квадрата.

**2. Сингулярное разложение (SVD)**

Любую матрицу можно записать как $X = U \Sigma V^T$, где $\Sigma$ — диагональная матрица с сингулярными числами. Тогда

$$
w = V \Sigma^{-1} U^T y
$$

Это один из самых устойчивых методов, но он тоже требует времени.

**Зачем это всё?**
Чтобы получить численно устойчивый ответ даже при мультиколлинеарности. Это важно, когда данных много или признаки сильно скоррелированы.

---

#### Приближенное численное решение (Градиентный спуск)

Когда данных очень много (миллионы объектов) или $D$ огромно, аналитическое решение становится непрактичным. Вместо этого мы ищем минимум итеративно, спускаясь по градиенту.

**Градиент функции потерь MSE:**

$$
\nabla_{w} L = \frac{2}{N} X^T (Xw - y)
$$

Для двух параметров $w_0, w_1$ это:

$$
\frac{\partial \text{MSE}}{\partial w_0} = -\frac{2}{N} \sum_{i=1}^N (y_i - \langle x_i, w \rangle)
$$

$$
\frac{\partial \text{MSE}}{\partial w_1} = -\frac{2}{N} \sum_{i=1}^N (y_i - \langle x_i, w \rangle) \cdot x_{i1}
$$

**Аналогия со спуском с горы:**

Представьте, что вы стоите в тумане и хотите спуститься в самую низкую точку долины. Вы не видите всей долины, но можете определить, в каком направлении склон самый крутой (градиент). Делаете шаг вниз, снова оцениваете склон — и так пока не дойдёте до ровного места (минимум). Темп обучения $\alpha$ — это размер шага. Если шаг слишком мал, будете долго идти; если слишком велик — можете перескочить дно.

**Алгоритм:**

1. Инициализировать веса $w$ (например, нулями или случайно).
2. Повторять $S$ раз:
   - Посчитать предсказания: $f = X \cdot w$
   - Посчитать ошибку: $\text{err} = f - y$
   - Посчитать градиент: $\text{grad} = \frac{2}{N} X^T \cdot \text{err}$
   - Обновить веса: $w = w - \alpha \cdot \text{grad}$

**Вычислительная сложность** — $O(NDS)$. Это быстрее, чем аналитика при больших $D$ (нет $D^3$), но требует подбора $\alpha$ и количества итераций $S$.


[Пример с ценой с квартирами](https://ivan-valuchev.yonote.ru/doc/primer-s-cenoj-s-kvartirami-9DXtThabg5)

---

#### Стохастический градиентный спуск (SGD)

Градиентный спуск всё ещё требует прохода по всей выборке на каждом шаге. Если $N$ огромно (миллиарды записей), даже один проход дорог. SGD вычисляет градиент на небольшой случайной подвыборке (батче) размера $B$:

$$
\nabla_{w}L(w, X, y) \approx \frac{1}{B} \sum_{t=1}^{B} \nabla_{w}L(w, x_{i_t}, y_{i_t})
$$

**Пример из жизни:**

Вы учите модель определять кошек по миллиону фото. Вместо того чтобы смотреть на все фото каждый раз, вы берёте 100 случайных фото, смотрите, насколько ошиблись, и корректируете веса. Затем берёте следующие 100 и т.д. Это намного быстрее и часто работает почти так же хорошо, как полный градиент.

**Преимущества SGD:**

1. **Быстрее** — вычисления на батче дешевле.
2. **Меньше памяти** — не нужно хранить всю выборку в памяти, достаточно текущего батча.
3. **Сходимость** — даже с шумом алгоритм сходится к оптимуму, если правильно подобрать темп обучения.

**Важно:** батчи должны быть случайными — перемешивайте данные перед обучением.

---

**Итог по разделу**

| Метод | Что делает | Когда использовать |
|----|----|----|
| **Аналитическое решение** | Даёт точные веса за один шаг | Маленький $D$ ($\leq 1000$) и $N$, отсутствие мультиколлинеарности |
| **QR / SVD** | Устойчивое вычисление тех же весов | Когда $X^T X$ плохо обусловлена |
| **Градиентный спуск** | Итеративно ищет минимум | Большой $N$ или $D$, когда аналитика дорога |
| **SGD** | Стохастическая версия градиентного спуска | Огромные данные, когда полный проход невозможен |

### Неградиентные методы

Помимо градиентных методов, существуют и другие численные подходы к решению задач линейной регрессии:

- **Пошаговая регрессия (Stepwise regression)** — последовательное добавление или удаление признаков.
- **Orthogonal matching pursuit (OMP)** — жадный алгоритм для поиска разреженных решений.
- **Метод наименьших углов (LARS, Least Angle Regression)** — эффективен в случае, когда число признаков больше числа объектов.

Эти методы менее универсальны, но могут быть полезны в специфических ситуациях.

### Регуляризация

**Краткое введение:** Решение задачи регрессии не всегда единственно. Если признаки линейно зависимы, веса могут быть сколь угодно большими. Это создаёт вычислительные трудности и делает модель неинтерпретируемой. Регуляризация решает эту проблему, добавляя штраф за большие веса.


**Зачем это нужно?**

Представьте, что вы учите модель предсказывать цены квартир. У вас есть 100 признаков (площадь, этаж, год постройки, близость к метро и т.д.), но данных всего 50 квартир. Модель может «запомнить» все 50 квартир идеально, но на новых данных будет ошибаться — это **переобучение**. Или представьте, что у вас есть два почти одинаковых признака: площадь в м² и площадь в сотках. Модель запутается, какой из них важнее, и веса станут огромными и нестабильными — это **мультиколлинеарность**.

**Что делает регуляризация?** Добавляет штраф за большие веса. Модель вынуждена выбирать не только точные, но и «скромные» веса — это улучшает её способность работать с новыми данными.

---

#### Общая идея

Обычная функция потерь (MSE) стремится просто уменьшить ошибку на обучающей выборке. Регуляризованная функция потерь добавляет к ней штраф:

$$
L_{\text{reg}}(w) = L(w) + \lambda \cdot \text{штраф}
$$

где $\lambda$ — коэффициент регуляризации. Чем больше $\lambda$, тем сильнее мы штрафуем большие веса.

**Важно:** вес $w_0$ (свободный член) обычно не регуляризуют, так как он задаёт базовый уровень и не должен штрафоваться.

---

#### L2-регуляризация (Ridge)

**Штраф:** сумма квадратов весов: $\lambda \sum w_j^2$

**Эффект:** все веса становятся меньше, но ни один не обнуляется.

**Пример (на пальцах):**

У вас есть два признака: площадь в м² ($x_1$) и площадь в сотках ($x_2 = x_1 / 100$). Без регуляризации модель может дать веса $w_1 = 10000$, $w_2 = -100$ (компенсируют друг друга). С Ridge модель выберет что-то вроде $w_1 = 100$, $w_2 = 0$ — веса станут меньше и стабильнее.

**Аналогия:**

Это как если бы вы пекли торт и за каждый лишний грамм сахара платили штраф. Вы всё равно положите сахар, но не слишком много.

**Где использовать:** всегда, когда есть мультиколлинеарность или много признаков. Ridge «сглаживает» веса.

**Формулы:**

- Добавка к функции потерь: $\lambda \|w\|_2^2$
- Аналитическое решение: $w = (X^T X + \lambda I)^{-1} X^T y$
- Градиент для SGD: $\nabla_w L_{\text{ridge}} = \frac{2}{N} X^T (Xw - y) + 2\lambda w$

---

#### L1-регуляризация (Lasso)

**Штраф:** сумма модулей весов: $\lambda \sum |w_j|$

**Эффект:** многие веса становятся **ровно нулевыми** — модель сама отбирает важные признаки.

**Пример (на пальцах):**

У вас 100 признаков, но только 3 действительно влияют на цену квартиры. Lasso обнулит веса для 97 неважных признаков, оставив только 3 важных. Это автоматический отбор признаков.

**Аналогия:**

Это как если бы у вас был бюджет на ингредиенты для торта, и вы могли купить только самое необходимо

е. Лишнее просто не влезает в бюджет.

**Где использовать:** когда признаков много, и вы подозреваете, что большинство из них неважны. Lasso помогает упростить модель.

**Особенность:** функция потерь недифференцируема в нуле (модуль имеет «угол»). Поэтому используют **субградиент**:

$$
\frac{\partial |w_i|}{\partial w_i} = \text{sign}(w_i) = 
\begin{cases}
1, & w_i > 0 \
-1, & w_i < 0 \
\text{любое число от } -1 \text{ до } 1, & w_i = 0
\end{cases}
$$

**Шаг обновления для SGD (для одного объекта):**

$$
w_i \mapsto w_i - \alpha \cdot \left( -2 (y_j - \langle w, x_j \rangle) x_{ji} + \lambda \cdot \text{sign}(w_i) \right)
$$

---

#### Сравнение L1 и L2

|    | L1 (Lasso) | L2 (Ridge) |
|----|----|----|
| **Штраф** | $\sum \vert w_j \vert$ | $\sum w_j^2$ |
| **Эффект** | Обнуляет неважные признаки | Уменьшает все веса, но не обнуляет |
| **Когда использовать** | Много признаков, нужен отбор | Мультиколлинеарность, стабильность |
| **Пример** | Выбор 5 важных слов из 1000 | Сглаживание весов при коррелирующих признаках |

#### Жизненный пример

Вы предсказываете зарплату по 50 признакам (образование, опыт, навыки). У вас 100 записей.

- **Без регуляризации:** модель может «запомнить» данные и дать странные веса: например, признак «знание Excel» получит вес +100000, а признак «знание Python» — -90000. Это бессмысленно.
- **С Ridge:** веса станут меньше и разумнее. «Знание Excel» даст +5000, «знание Python» — +15000.
- **С Lasso:** модель может вообще обнулить признак «знание Excel», если он неважен, и оставить только «знание Python» и «опыт».

---

**Важно:** L1- и L2-регуляризацию можно применять к любой функции потерь, не только к MSE, — например, в задачах классификации.

---

#### Итог

- Регуляризация — это штраф за большие веса.
- L2 (Ridge) — уменьшает все веса, стабилизирует модель.
- L1 (Lasso) — обнуляет неважные признаки, упрощает модель.
- Выбор между L1 и L2 зависит от задачи: если нужно упростить модель — берите L1, если стабилизировать — L2.
- $\lambda$ — гиперпараметр, который подбирают отдельно (чем он больше, тем сильнее регуляризация).

### Другие функции потерь для регрессии

Стохастический градиентный спуск можно очевидным образом обобщить для решения задачи линейной регрессии с любой другой функцией потерь, не только квадратичной: ведь всё, что нам нужно от неё, — это чтобы у функции потерь был градиент. На практике это делают редко, но, тем не менее, рассмотрим ещё пару вариантов.  

**MAE (Mean Absolute Error):**

$$
MAE(y, \hat{y}) = \frac{1}{N} \sum_{i=1}^{N} |y_i - \hat{y}_i|
$$

Менее чувствительна к выбросам по сравнению с MSE. MSE приближает условное математическое ожидание $\mathbb{E}[y \mid x]$, а MAE — условную медиану.

**Пример расчёта MAE и MSE (сравнение):**

Пусть реальные значения: $y = [3, 5, 2.5]$, предсказания модели: $\hat{y} = [2.5, 5, 3]$.

- Ошибки: $[0.5, 0, 0.5]$
- MAE = $\frac{0.5 + 0 + 0.5}{3} = 0.333$
- MSE = $\frac{0.5^2 + 0^2 + 0.5^2}{3} = \frac{0.25 + 0 + 0.25}{3} = 0.167$

Теперь добавим выброс: $y = [3, 100, 2.5]$, предсказания те же $\hat{y} = [2.5, 5, 3]$.

- Ошибки: $[0.5, 95, 0.5]$
- MAE = $\frac{0.5 + 95 + 0.5}{3} = 32.0$
- MSE = $\frac{0.25 + 9025 + 0.25}{3} \approx 3008.5$

Видно, что MSE **сильно** выросла из-за одного выброса, а MAE выросла, но не так драматично. MAE устойчивее к выбросам.

---

**MAPE (Mean Absolute Percentage Error):**

$$
MAPE(y, \hat{y}) = \frac{1}{N} \sum_{i=1}^{N} \left|\frac{\hat{y}_i - y_i}{y_i}\right|
$$

Позволяет оценивать относительную ошибку, что полезно для данных разного масштаба.

**Пример расчёта MAPE:**

Реальные значения: $y = [1000, 2000, 3000]$, предсказания: $\hat{y} = [900, 2200, 2900]$.

- Относительные ошибки:
  $\left|\frac{900-1000}{1000}\right| = 0.1$
  $\left|\frac{2200-2000}{2000}\right| = 0.1$
  $\left|\frac{2900-3000}{3000}\right| \approx 0.033$
- MAPE = $\frac{0.1 + 0.1 + 0.033}{3} \approx 0.0778$ (или 7.78%)

MAPE показывает, что модель ошибается в среднем на \~7.8% от истинных значений. Это удобно, когда важна относительная точность (например, в задачах прогнозирования продаж).

---

**Huber loss (потеря Хубера):**

$$
L(f, X, y) = \sum_{i=1}^N h_\delta (y_i - \langle w, x_i \rangle)
$$

где

$$
h_\delta(z) = 
\begin{cases}
\frac{1}{2}z^2, & |z| \le \delta \
\delta(|z| - \frac{1}{2}\delta), & |z| > \delta
\end{cases}
$$

Число $\delta$ — гиперпараметр. Эта функция сочетает свойства MSE (для малых ошибок) и MAE (для больших ошибок, чтобы уменьшить влияние выбросов).

**Пример расчёта Huber loss:**

Пусть $\delta = 1$. Рассмотрим три ошибки: $z = 0.5$, $z = 2$, $z = -3$.

- Для $z = 0.5$ ($|z| \le 1$): $h_{1}(0.5) = \frac{1}{2} \cdot 0.5^2 = 0.125$
- Для $z = 2$ ($|z| > 1$): $h_{1}(2) = 1 \cdot (2 - 0.5) = 1.5$
- Для $z = -3$ ($|z| > 1$): $h_{1}(-3) = 1 \cdot (3 - 0.5) = 2.5$

Сравним с MSE и MAE для этих же ошибок:

- MSE: $0.25 + 4 + 9 = 13.25$
- MAE: $0.5 + 2 + 3 = 5.5$
- Huber: $0.125 + 1.5 + 2.5 = 4.125$

Huber даёт штраф, промежуточный между MSE и MAE, и при больших ошибках (как MAE) не позволяет выбросам слишком сильно влиять на модель.


🧠 Итог — какую функцию потерь выбрать?

| Функция потерь | Когда использовать |
|:---|:---|
| **MSE** | Когда данные чистые, без выбросов, и важна точность предсказаний (например, физические измерения). |
| **MAE** | Когда в данных есть выбросы, и вы не хотите, чтобы модель на них ориентировалась. |
| **MAPE** | Когда важна относительная ошибка (проценты), например, в бизнес-задачах. |
| **Huber** | Когда вы хотите устойчивость к выбросам, но при этом сохранить гладкость функции потерь (хорошо для градиентного спуска). |

### Линейная классификация (Бинарная)

Цель: найти разделяющую гиперплоскость, которая отделяет объекты одного класса от другого. Для бинарной классификации таргеты обычно кодируются как $y_i \in {-1, 1}$.

Предсказание класса для объекта $x_i$:

$$
\hat{y}_i = \text{sign}(\langle w, x_i \rangle)
$$

---

#### Почему нельзя решать классификацию как регрессию?

Мы могли бы попробовать предсказывать числа $-1$ и $1$ с помощью MSE, а потом брать знак. Но это работает плохо:

1. Регрессия почти не штрафует за ошибки на объектах, которые лежат близко к разделяющей плоскости, но с неправильной стороны.
2. Ошибкой считается предсказание $5$ вместо $1$, хотя на самом деле важен только знак, а не модуль.

Поэтому нужна специальная функция потерь для классификации.

---

#### Отступ (margin)

Ключевое понятие — **отступ**:

$$
M_i = y_i \langle w, x_i \rangle
$$

- Если $M_i > 0$, объект классифицирован **верно**.
- Если $M_i < 0$, объект классифицирован **неверно**.
- Чем больше $|M_i|$, тем "увереннее" классификатор.

**Пример расчёта отступа:**

Пусть $w = (1, 2)$, объект $x = (3, -1)$ с классом $y = 1$.

$$
M = 1 \cdot (1 \cdot 3 + 2 \cdot (-1)) = 1 \cdot (3 - 2) = 1
$$

$M > 0$ → объект классифицирован верно.

Если бы класс был $y = -1$:

$$
M = -1 \cdot (3 - 2) = -1
$$

$M < 0$ → объект классифицирован неверно.

---

#### Misclassification loss (кусочно-постоянная функция)

Misclassification loss делает ровно одну простую вещь:

$$
L = 
\begin{cases}
0, & \text{если } \hat{y} = y \text{ (предсказал правильно)} \
1, & \text{если } \hat{y} \neq y \text{ (предсказал неправильно)}
\end{cases}
$$

Вот и всё. Это как лампочка, которая загорается (1), если модель ошиблась, и гаснет (0), если угадала.

---

Почему эта функция не годится для обучения?

Именно из-за этой "грубости" (либо 0, либо 1) она не годится для обучения:

- Если модель ошиблась, она говорит: *"Ты ошибся"*. Но **не говорит**, насколько сильно ошибся (на 0.1 или на 100) и **куда крутить веса**, чтобы исправиться (градиент равен нулю).
- Если модель угадала, она говорит: *"Молодец"*. Но **не говорит**, была ли это уверенная победа (отступ = 100) или счастливая случайность (отступ = 0.1). Веса тоже не двигаются.

---

Как решается проблема?

Поэтому мы и используем другие функции (**Hinge**, **Log Loss**) — они вместо сухой лампочки дают нам **градусник**: показывают, насколько мы близки к ошибке или к правильному ответу, и позволяют нам "подкручивать" веса.

А **Misclassification loss** остаётся нашим **финальным счётчиком**, чтобы просто посчитать, сколько раз модель ошиблась на тестовых данных.


Мы хотим минимизировать число ошибок:

$$
\sum_i [y_i \langle w, x_i \rangle < 0] \longrightarrow \min_w
$$

Это функция потерь равна $1$, если отступ отрицательный, и $0$, если положительный. Она кусочно-постоянная, её нельзя оптимизировать градиентными методами (производная равна нулю везде, где существует). Поэтому используют её гладкие приближения:

- **Ошибка перцептрона** ($\max(0, -M)$)
- **Hinge Loss** ($\max(0, 1 - M)$)
- **Log Loss** ($-\log p$)       

---

#### Исходные данные для расчета 

- Один признак: $x = 2$
- Правильный класс: $y = 1$
- Текущий вес: $w = -0.5$ (модель ошибается, потому что $w \cdot x = -1 < 0$, а должно быть $> 0$)
- Скорость обучения: $\alpha = 0.1$

#### Ошибка перцептрона

Используется функция потерь, штрафующая только за неправильно классифицированные объекты, пропорционально их отступу:

$$
L(w, x, y) = \lambda \|w\|_2^2 + \sum_{i} \max(0, -y_i \langle w, x_i \rangle)
$$

**Градиент:**

$$
\nabla_w L(w, x, y) = 2\lambda w + \sum_i 
\begin{cases} 
0, & y_i \langle w, x_i \rangle > 0 \
-y_i x_i, & y_i \langle w, x_i \rangle \le 0
\end{cases}
$$

**Пример расчёта:**

**Идея:** Штрафуем только неправильные объекты. Если объект правильный — штраф 0.

Функция потерь (для одного объекта):

$$
L = \max(0, -y \cdot w \cdot x)
$$

**Градиент:**

- Если $y \cdot w \cdot x > 0$ (правильно) → градиент = 0.
- Если $y \cdot w \cdot x \le 0$ (неправильно) → градиент = $-y \cdot x$.

---

**Шаг 1: Проверяем, правильный ли объект**

$$
y \cdot w \cdot x = 1 \cdot (-0.5) \cdot 2 = -1
$$

$-1 < 0$ → объект неправильный.

---

**Шаг 2: Считаем градиент**

Так как объект неправильный, используем вторую ветку:

$$
\text{градиент} = -y \cdot x = -1 \cdot 2 = -2
$$

---

**Шаг 3: Обновляем вес**

$$
w_{\text{новый}} = w_{\text{старый}} - \alpha \cdot \text{градиент} = -0.5 - 0.1 \cdot (-2) = -0.5 + 0.2 = -0.3
$$

Вес увеличился с $-0.5$ до $-0.3$. Он стал ближе к нулю, но всё ещё отрицательный. Если мы продолжим, он станет положительным и исправит ошибку.

---

**__Что будет, если объект правильный?__**

Пусть $w = 1$ (правильно, так как $1 \cdot 2 = 2 > 0$).

$$
y \cdot w \cdot x = 1 \cdot 1 \cdot 2 = 2 > 0
$$

Градиент = 0

Обновление:

$$
w_{\text{новый}} = 1 - 0.1 \cdot 0 = 1
$$

Вес не меняется. Модель уже правильно классифицирует, и она не пытается улучшить уверенность (не увеличивает отступ).



---

#### Hinge Loss (SVM)

Стремится не только правильно классифицировать, но и максимизировать зазор между классами:

$$
L(w, x, y) = \lambda \|w\|_2^2 + \sum_{i} \max(0, 1 - y_i \langle w, x_i \rangle)
$$

**Градиент:**

$$
\nabla_w L(w, x, y) = 2\lambda w + \sum_i 
\begin{cases} 
0, & 1 - y_i \langle w, x_i \rangle \le 0 \
-y_i x_i, & 1 - y_i \langle w, x_i \rangle > 0
\end{cases}
$$

**Почему Hinge Loss максимизирует зазор?**

Ширина разделительной полосы равна $\frac{2}{\|w\|_2}$. Чтобы её увеличить, нужно уменьшить $\|w\|_2$. Поэтому в функцию потерь добавляют регуляризатор $\lambda \|w\|_2^2$ — минимизация этого слагаемого эквивалентна максимизации ширины полосы.

**Суть:** Объекты, которые классифицированы верно, но находятся близко к разделяющей плоскости ($0 \le M_i < 1$), всё ещё вносят вклад в штраф и "отодвигают" плоскость от себя. Это приводит к максимизации зазора.

**Пример расчёта:**

**Идея:** Штрафуем объекты, которые находятся внутри полосы ($M < 1$), даже если они правильно классифицированы. Это заставляет модель увеличивать отступ.

Функция потерь (для одного объекта):

$$
L = \max(0, 1 - y \cdot w \cdot x)
$$

**Градиент:**

- Если $y \cdot w \cdot x \ge 1$ (далеко от границы, правильно) → градиент = 0.
- Если $y \cdot w \cdot x < 1$ (внутри полосы или ошибка) → градиент = $-y \cdot x$.

---

**Шаг 1: Проверяем условие**

$$
y \cdot w \cdot x = 1 \cdot (-0.5) \cdot 2 = -1
$$

$-1 < 1$ → объект внутри полосы (даже хуже, он неправильный).

---

**Шаг 2: Считаем градиент**

$$
\text{градиент} = -y \cdot x = -1 \cdot 2 = -2
$$

---

**Шаг 3: Обновляем вес**

$$
w_{\text{новый}} = -0.5 - 0.1 \cdot (-2) = -0.5 + 0.2 = -0.3
$$

Вес увеличился (стал ближе к нулю). Тот же шаг, что и у перцептрона, потому что объект неправильный. Но теперь посмотрим на правильный, но близкий объект.

---

**__Что будет, если объект правильный, но близкий к границе?__**

Пусть $w = 0.4$, $x = 2$, $y = 1$.

$$
y \cdot w \cdot x = 1 \cdot 0.4 \cdot 2 = 0.8
$$

$0.8 < 1$ → объект внутри полосы.

Градиент = $-y \cdot x = -1 \cdot 2 = -2$

Обновление:

$$
w_{\text{новый}} = 0.4 - 0.1 \cdot (-2) = 0.4 + 0.2 = 0.6
$$

Вес увеличился! Модель «отодвигает» объект от границы, увеличивая отступ.

---

**__Что будет, если объект далеко от границы?__**

Пусть $w = 2$, $x = 2$, $y = 1$.

$$
y \cdot w \cdot x = 1 \cdot 2 \cdot 2 = 4
$$

$4 \ge 1$ → объект далеко, всё хорошо.

Градиент = 0

Обновление:

$$
w_{\text{новый}} = 2 - 0.1 \cdot 0 = 2
$$

Вес не меняется. Модель удовлетворена.

#### **__Что такое логит (logit)__**

Логит — это сырая линейная оценка до sigmoid или softmax. Не финальный ответ, а промежуточное число (может быть любым: $-5$, $0$, $100$).

**Формула:**

$$
z = \langle w, x \rangle = w_0 + w_1 x_1 + w_2 x_2 + \dots
$$

(Если в $x$ добавлен признак «1», сдвиг $w_0$ уже внутри скалярного произведения — см. *Пояснение*.)

**Связь с тем, что уже было выше**

| Формула | Смысл |
|----|----|
| $z = \langle w, x_i \rangle$ | сырая линейная оценка |
| $M_i = y_i \cdot z$ | логит $\times$ метка класса (отступ) |
| $\text{sign}(z)$ | смотрим только на знак логита (класс) |

Перцептрон и Hinge штрафуют через отступ $M$. Логистическая регрессия сначала считает $z$, потом превращает его в вероятность.

**Логит vs линейная регрессия**

|    | Линейная регрессия | Логит |
|----|----|----|
| Формула | $\hat{y} = \langle w, x \rangle$ | $z = \langle w, x \rangle$ |
| На выходе | сразу число (цена, рост…) | промежуточное значение |
| Дальше | ничего | sigmoid → вероятность (2 класса) или softmax → вероятности ($K$ классов) |

**Вывод:** формула одна и та же, но в регрессии это ответ, а в классификации — первый шаг.

**Что дальше**

| Задача | Что делаем с логитом |
|----|----|
| 2 класса | $p = \sigma(z) = \dfrac{1}{1 + e^{-z}}$ → см. «Логистическая регрессия» |
| $K$ классов | логиты $b_k(x) = \langle w_k, x \rangle$ → softmax → см. «Многоклассовая классификация» |

**Шпаргалка**

| Термин | Что это |
|----|----|
| Логит | $z = \langle w, x \rangle$ |
| Сигмоида | $\sigma(z)$ — вероятность для 2 классов |
| Логистическая регрессия | логит + sigmoid |
| Softmax | несколько логитов → вероятности по классам |

#### Логистическая регрессия

 Сначала считаем логит (см. раздел выше):  

$$
z = w \cdot x = -0.5 \cdot 2 = -1
$$

  

Затем применяем sigmoid для получения вероятности положительного класса:

   

$$
p = \sigma(z) = \frac{1}{1 + e^{-z}} = \frac{1}{1 + e^{-(-1)}} = \frac{1}{1 + e^{1}} \approx \frac{1}{1 + 2.718} \approx 0.269
$$

Вероятность положительного класса ($y = 1$) составляет ≈ 26.9%.

---

**Обучение (функция потерь)**

Веса подбираются методом максимума правдоподобия. Так как у нас всего один объект с $y = 1$, логарифм правдоподобия для этого объекта равен:

$$
\ell = y \cdot \log(p) + (1 - y) \cdot \log(1 - p) = \log(p)
$$

Что эквивалентно минимизации функции потерь (отрицательное логарифмическое правдоподобие) для данного объекта:

$$
L(w) = -\log(\sigma(w \cdot x))
$$

Подставляя числа:

$$
L = -\log(0.269) \approx 1.313
$$

---

**Вывод градиента (для одного объекта, скалярный случай)**

Используем свойство производной сигмоиды:

$$
\frac{d\log\sigma(z)}{dz} = \sigma(-z)
$$

По правилу цепочки (так как $z = w \cdot x$, производная по $w$ дает множитель $x$):

$$
\frac{dL}{dw} = -\frac{d\log\sigma(w \cdot x)}{dw} = -\sigma(-w \cdot x) \cdot x
$$

Упростим выражение, используя свойство $\sigma(-z) = 1 - \sigma(z)$:

$$
\frac{dL}{dw} = -(1 - \sigma(w \cdot x)) \cdot x = -(1 - p) \cdot x
$$

Учитывая, что $y = 1$, это выражение полностью эквивалентно общей формуле градиента:

$$
\frac{dL}{dw} = -x \cdot (y - p)
$$

Подставляем наши числа:

$$
\frac{dL}{dw} = -2 \cdot (1 - 0.269) = -2 \cdot 0.731 = -1.462
$$

---

**Обновление веса (шаг градиентного спуска)**

Обновление веса выполняется по правилу:

$$
w_{\text{новый}} = w - \alpha \cdot \frac{dL}{dw}
$$

Подставляем значения:

$$
w_{\text{новый}} = -0.5 - 0.1 \cdot (-1.462) = -0.5 + 0.1462 = -0.3538
$$

**Важно:** в отличие от перцептрона, где вес сдвинулся бы сильнее (на $\alpha \cdot 2 = 0.2$), здесь изменение составило всего $+0.1462$. Это произошло потому, что градиент логистической регрессии зависит от разницы между правильным классом и предсказанной вероятностью ($1 - 0.269 = 0.731$). Чем ближе модель будет к уверенному предсказанию ($p \to 1$), тем меньше будет градиент и тем более плавными станут обновления весов.

**Перцептрон** ($w = -0.5 \to -0.3$):

Объект неправильный ($M = -1$), поэтому шаг был большим ($+0.2$). Как только станет правильным ($w = 1$), вес замрёт.

**Hinge Loss** ($w = -0.5 \to -0.3$, а потом $0.4 \to 0.6$):

- Если объект неправильный — двигает так же, как перцептрон ($+0.2$).
- Если объект правильный, но близко ($w = 0.4$, $M = 0.8$) — продолжает двигать ($+0.2$), чтобы отодвинуть его за $M \ge 1$.
- Если уже далеко ($w = 2$, $M = 4$) — замирает.

**Log Loss** ($w = -0.5 \to -0.3538$):
Шаг всего $+0.1462$. Меньше, чем у других, потому что модель штрафуется пропорционально разнице между правильным классом и вероятностью ($1 - 0.269 = 0.731$). Она никогда не замирает, но когда $p$ станет $0.99$, шаг будет почти незаметным.

### Многоклассовая классификация

Пусть каждый объект нашей выборки относится к одному из $K$ классов: $\mathbb{Y} = {1, \dots, K}$. Чтобы предсказывать эти классы с помощью линейных моделей, необходимо свести задачу многоклассовой классификации к набору бинарных задач.

#### Один против всех (one-vs-all)

Обучается $K$ линейных классификаторов $b_1(x), \dots, b_K(x)$, выдающих оценки принадлежности классам $1, \dots, K$ соответственно. В случае линейных моделей классификаторы имеют вид:

$$
b_k(x) = \text{sgn}(\langle w_k, x \rangle + w_{0k})
$$

Классификатор с номером $k$ обучается по выборке $(x_i, 2[y_i = k] - 1)_{i=1}^N$, то есть он отличает $k$-й класс от всех остальных. Итоговый классификатор выдаёт класс, соответствующий самому уверенному из бинарных алгоритмов:

$$
a(x) = \arg\max_k (\langle w_k, x \rangle + w_{0k})
$$

**Проблема подхода:** каждый классификатор обучается на своей выборке, и значения линейных функций могут иметь разные масштабы, из-за чего сравнивать их некорректно.

#### Все против всех (all-vs-all)

Обучается $\binom{K}{2}$ классификаторов $b_{ij}(x)$ для каждой пары классов $i, j$:

$$
b_{ij}(x) = \text{sgn}(\langle w_{ij}, x \rangle + w_{0,ij})
$$

Классификатор $b_{ij}(x)$ настраивается по подвыборке, содержащей только объекты классов $i$ и $j$. Для классификации нового объекта каждый бинарный классификатор голосует за свой класс; побеждает класс, набравший большинство голосов:

$$
a(x) = \arg\max_k \sum_{i=1}^K \sum_{j \neq i} [b_{ij}(x) = k]
$$

**Проблема подхода:** возможны ситуации, когда голоса разделяются поровну (например, каждый класс получает по одному голосу), и для таких точек нет способа выдать обоснованное предсказание.

#### Многоклассовая логистическая регрессия (softmax)

<https://www.youtube.com/watch?v=Sm04Fub2f6o>


Некоторые методы бинарной классификации можно напрямую обобщить на случай многих классов. Для многоклассовой логистической регрессии строится $K$ линейных моделей:

$$
b_k(x) = \langle w_k, x \rangle + w_{0k}
$$

 bk​(x) — это логит класса kk. Softmax превращает набор логитов в вероятности.  


Вероятность $k$-го класса вычисляется с помощью оператора **softmax**:

$$
P(y = k \mid x, w) = \frac{\exp(\langle w_k, x \rangle + w_{0k})}{\sum_{j=1}^K \exp(\langle w_j, x \rangle + w_{0j})}
$$

Обучение ведётся методом максимального правдоподобия:

$$
\sum_{i=1}^N \log P(y = y_i \mid x_i, w) \rightarrow \max_{w_1, \dots, w_K}
$$

---

#### Более простое пояснение

Это последний крупный раздел по линейным моделям — многоклассовая классификация. Здесь мы переходим от задачи «кот или собака» к задаче «кот, собака, хомяк, попугай».

---

Что такое многоклассовая классификация?

- **Бинарная классификация** — два класса: спам / не спам.
- **Многоклассовая классификация** — три и более классов: например, распознавание цифр (0–9), виды цветов (3–5 видов), типы животных.

**Проблема:** линейная модель по умолчанию умеет разделять только на два класса (через знак скалярного произведения). Как быть, если классов 10? Надо свести многоклассовую задачу к нескольким бинарным.

Есть три основных подхода:

1. **Один против всех** (one-vs-all) — классический, простой.
2. **Все против всех** (all-vs-all) — более надёжный, но дорогой.
3. **Многоклассовая логистическая регрессия** (softmax) — самый правильный и современный.

---

**1️⃣ Один против всех (One-vs-All, OVA)**

Для каждого класса мы обучаем отдельный бинарный классификатор, который отвечает на вопрос: «Этот объект принадлежит классу $k$ или НЕ принадлежит?»

- Классификатор №1: «Это кот?» (да / нет)
- Классификатор №2: «Это собака?» (да / нет)
- Классификатор №3: «Это хомяк?» (да / нет)

Итого для $K$ классов мы обучаем $K$ бинарных моделей.

🧠 Как это работает на практике?

**Обучение:**

Для классификатора $k$ мы берём все объекты и перекодируем их метки:

- Если объект принадлежит классу $k$ → ставим метку $+1$.
- Если объект не принадлежит классу $k$ → ставим метку $-1$.

Теперь обучаем обычную бинарную модель (например, SVM или логистическую регрессию) отличать класс $k$ от всех остальных.

**Предсказание:**

Для нового объекта $x$ мы подаём его на все $K$ классификаторов. Каждый выдаёт своё значение (взвешенную сумму $\langle w_k, x \rangle + w_{0k}$). Выбираем тот класс, у которого значение максимальное (самый «уверенный» классификатор).

$$
a(x) = \arg\max_k (\langle w_k, x \rangle + w_{0k})
$$

✅ Плюсы

- Простой, логичный, легко реализуется.
- Если у вас уже есть код для бинарной классификации, его легко адаптировать.

❌ Минусы

- **Дисбаланс классов.** Если классов много, каждый классификатор обучается на несбалансированной выборке (например, класс 1 — 100 объектов, классы 2–10 — 900 объектов). Модель может «забить» на маленький класс.
- **Разные масштабы.** У каждого классификатора свои веса, и значения $\langle w_k, x \rangle$ могут быть в разных диапазонах. Сравнивать их напрямую — некорректно. Например, один классификатор даёт значения от -10 до 10, а другой — от -100 до 100. Мы не можем просто взять максимум, потому что масштабы разные.

**Аналогия:** представьте, что у вас три учителя, каждый ставит оценки по своей шкале. Один ставит от 1 до 5, другой от 1 до 10, третий от 1 до 100. Нельзя просто выбрать того, у кого оценка выше — нужно привести их к общему знаменателю.

---

**2️⃣ Все против всех (All-vs-All, AVA)**

Для каждой пары классов обучаем отдельный бинарный классификатор, который отвечает на вопрос: «Это класс $i$ или класс $j$?»

- Классификатор (кот vs собака)
- Классификатор (кот vs хомяк)
- Классификатор (собака vs хомяк)

Итого для $K$ классов нужно обучить $\binom{K}{2} = \frac{K(K-1)}{2}$ моделей.

🧠 Как это работает на практике?

**Обучение:**

Для каждой пары классов $(i, j)$ берём только объекты этих двух классов и обучаем бинарный классификатор отличать $i$ от $j$.

**Предсказание:**

Для нового объекта $x$ запускаем все классификаторы. Каждый голосует за один из двух классов. После того как все проголосовали, считаем голоса для каждого класса. Побеждает тот, у кого больше голосов.

$$
a(x) = \arg\max_k \sum_{i=1}^K \sum_{j \neq i} [b_{ij}(x) = k]
$$

✅ Плюсы

- Более надёжен, чем OVA, потому что каждый классификатор обучается на сбалансированной выборке (ровно два класса).
- Голосование даёт более стабильный результат.

❌ Минусы

- **Сложность:** при $K = 10$ нужно обучить 45 моделей, при $K = 100$ — 4950. Это дорого.
- **Проблема «ничьей».** Может случиться, что голоса разделятся поровну (например, каждый класс получил по одному голосу). Тогда у нас нет способа выбрать победителя. На практике такие области (серые зоны) возникают на стыке классов.

**Аналогия:** это как круговой турнир в спорте. Каждый играет с каждым. Победитель определяется по сумме побед. Но если у всех одинаковое количество побед — ничья.

---

**3️⃣ Многоклассовая логистическая регрессия (Softmax)**

Вместо того чтобы разбивать задачу на бинарные, мы строим одну модель, которая сразу выдаёт вероятности для всех классов.

Строим $K$ линейных моделей (по одной на класс):

$$
b_k(x) = \langle w_k, x \rangle + w_{0k}
$$

Затем применяем оператор **softmax**, который превращает набор чисел в вероятности, суммирующиеся в 1:

$$
P(y = k \mid x, w) = \frac{e^{b_k(x)}}{\sum_{j=1}^K e^{b_j(x)}}
$$

- Экспонента $e^{b_k}$ «усиливает» большие значения.
- Знаменатель нормирует всё так, чтобы сумма вероятностей была равна 1.

🧠 Как это работает на практике?

**Обучение:**

Мы максимизируем логарифм правдоподобия (как в бинарной логистической регрессии, только для многих классов):

$$
\sum_{i=1}^N \log P(y = y_i \mid x_i, w) \to \max
$$

Это эквивалентно минимизации функции потерь (кросс-энтропия).

✅ Плюсы

- **Единая модель.** Обучается сразу на всех классах.
- **Вероятности.** На выходе получаем интерпретируемые вероятности для каждого класса.
- Градиент вычисляется просто и эффективно — можно использовать градиентный спуск.

❌ Минусы

- Чуть сложнее для понимания, чем OVA/AVA.
- Если классов очень много (тысячи), softmax становится дорогим (нужно считать экспоненты для всех классов). Для таких случаев используют приближения (например, Negative Sampling).

**Аналогия:** это не турнир, а рейтинг. Мы даём каждому классу оценку, а потом превращаем эти оценки в проценты, чтобы их можно было сравнивать. Чем выше оценка, тем больше процент.

---

**📊 Сравнение трёх подходов (таблица)**

| Характеристика | One-vs-All (OVA) | All-vs-All (AVA) | Softmax |
|:---|:---|:---|:---|
| **Сколько моделей** | $K$ | $\binom{K}{2}$ | Одна модель |
| **Интерпретация** | Оценки | Голоса | Вероятности |
| **Дисбаланс классов** | Есть проблема |   **Меньше проблемы (на уровне пар)**   | Нет проблемы (но данные должны быть сбалансированы) |
| **Сложность обучения** | Низкая ($K$ моделей) | Высокая ($K^2$ моделей) | Средняя (одна модель, но с $K$ параметрами) |
| **Когда использовать** | Классов мало, важна скорость | Классов мало, важна стабильность | Классов не очень много, нужны вероятности |

| Задача | Рекомендация |

💡 Пример для закрепления

Представьте, что вы классифицируете рукописные цифры (0–9). $K = 10$.

- **One-vs-All:** обучаете 10 моделей. Каждая отвечает на вопрос «Это цифра 3?» или «Это не цифра 3?» При предсказании выбираете ту, у которой ответ наиболее уверенный.
- **All-vs-All:** обучаете 45 моделей (каждая пара цифр). При предсказании каждая пара голосует. Побеждает цифра с большинством голосов.
- **Softmax:** обучаете одну модель с 10 выходами. Она сразу выдаёт вероятности: «Это 0 с вероятностью 80%, это 1 с вероятностью 2%...». Выбираете класс с максимальной вероятностью.

На практике для цифр чаще всего используют **Softmax**, потому что он даёт вероятности и обучается быстрее, чем 45 моделей.

---

✅ Итог

| Подход | Суть |
|:---|:---|
| **One-vs-All** | Каждый класс против всех остальных |
| **All-vs-All** | Каждая пара классов друг против друга |
| **Softmax** | Одна модель, выдающая вероятности для всех классов |

**Главный вывод:** все три метода работают, но **softmax** — самый «правильный» с точки зрения теории вероятностей и чаще всего используется на практике.

### Масштабируемость линейных моделей

SGD позволяет обучению хорошо масштабироваться по числу объектов, так как можно не загружать их целиком в оперативную память. Однако возникают проблемы, когда признаков очень много или их количество заранее неизвестно. Такие ситуации возникают, например:

- **Классификация текстов** (мешок слов): размерность может составлять сотни тысяч.
- **Предсказание кликов по рекламе**: размерность может достигать $10^{16}$, при этом постоянно появляются новые пользователи и веб-страницы.

Для борьбы с этими проблемами используются следующие подходы:

1. **Разреженное кодирование:** несмотря на огромную полную размерность, количество ненулевых элементов в каждом объекте невелико. Вместо плотного вектора хранится словарь с индексами и значениями ненулевых элементов.
2. **Хеширование признаков (hashing trick):** веса хранятся в хеш-таблице, а индекс вычисляется по формуле $\text{hash}(\text{feature}) \bmod \text{tablesize}$. Несколько фич могут разделять общий вес, что позволяет сжать вектор весов на много порядков ценой небольших потерь в качестве. Пример библиотеки с такой реализацией — **vowpal wabbit**.
3. **Распределённое хранение:** если качество критично и сжатие недопустимо, задачу решают распределённо, храня признаки в шардированной хеш-таблице на нескольких серверах. Обучающий сервер запрашивает нужные веса, считает градиент и отправляет его обратно для применения. Схема обладает бесконечной масштабируемостью, но применима в ограниченном числе задач.

---

### Заключение

На линейную модель можно смотреть как на однослойную нейросеть, поэтому многие методы, разработанные для них, сейчас переиспользуются в задачах глубокого обучения. Базовые подходы к регрессии, классификации и оптимизации выглядят абсолютно так же. Несмотря на то, что линейные модели сегодня применяются редко, их компоненты и принципы построения знать очень полезно.

Решение любой ML-задачи состоит из трёх компонентов:

1. Выбор функции потерь.
2. Выбор параметризованного класса моделей.
3. Выбор способа оптимизации.

Эти базовые принципы останутся неизменными при изучении других моделей и оптимизаторов.v
