# ЧАСТЬ 1. ЧТО ТАКОЕ РЕШАЮЩЕЕ ДЕРЕВО

---

## 1. Идея одной фразой

**Решающее дерево** предсказывает ответ, применяя **последовательность простых правил** (предикатов): «если признак ≤ порога — иди влево, иначе — вправо».

> Это похоже на то, как человек принимает решения:
>
> «Площадь > 50?» → да → «Этаж ≥ 5?» → нет → цена ≈ 8 млн.

---

### 1.1. Как выглядит предсказание

```
              [x1 ≤ 0.5?]
             /            \
      [x2 ≤ 0.3?]        [x2 ≤ 0.7?]
       /      \            /      \
    класс1  класс2     класс3  класс4
```

1. Стартуем из **корня**.
2. В каждом **узле** смотрим предикат.
3. Если предикат **верен** → обычно вправо, иначе → влево (в статье: порог по признаку).
4. Дошли до **листа** → берём записанный ответ (класс / число / вероятности).

Каждый предикат режет пространство признаков на **две части**.

Итог: плоскость разбита на **прямоугольники**, в каждом — **одно** предсказание.

> Дерево делает **кусочно-постоянную** аппроксимацию: внутри области ответ константа.

**Определение кусочно-постоянной аппроксимации:** Дерево режет пространство признаков на **прямоугольные области**. Внутри каждой области ответ — **одна и та же константа**.

**Почему «кусочно»:** Пространство состоит из **кусков** (прямоугольников), а не из одной гладкой поверхности.

**Почему «постоянная»:** Внутри куска ответ **не меняется**. Все объекты, попавшие в один лист, получают **одинаковый** прогноз.

**Аналогия: корзины с яблоками**

Ты **разложил** яблоки по **корзинам**:

- Корзина 1: **красные** яблоки.
- Корзина 2: **зелёные** яблоки.

**Что бы ты ни достал** из корзины 1 — это **красное** яблоко. **Все** яблоки в корзине 1 — **красные**.

**Дерево так же:** каждая «корзина» (лист) содержит объекты с **одним** ответом. **Все** объекты в листе получают **один и тот же** прогноз.

Если квартира 35 м² и квартира 45 м² попали в **один и тот же лист** — модель выдаст им **одну и ту же цену**.

**Почему так происходит**

Дерево **не смотрит** на точный метраж. Оно смотрит **только на пороги**.

**Пример вопроса в дереве:**

> «Площадь > 50?»

- 35 м² → **Нет** (≤ 50).
- 45 м² → **Нет** (≤ 50).

Для дерева **оба ответа одинаковые** — «Нет». Оно **не различает** 35 и 45. Для него это **одна и та же** группа.

Дальше дерево задаёт **следующие вопросы**. Если 35 и 45 м² проходят **все** пороги **одинаково** — они попадают в **один лист**.

---

### 1.2. Определение

Бинарное дерево, где:

| Вершина | Что приписано |
|:---|:---|
| **Внутренняя** $v$ | предикат $\beta_v(x)$ |
| **Лист** $v$ | прогноз $c_v$ (число, класс или вектор вероятностей) |

**«Внутренняя вершина»**

**Внутренняя** — значит, **не лист**. Это узел **внутри** дерева, где задаётся **вопрос**.

**Что приписано:** предикат $\beta_v(x)$ — **условие**.

**Пример:** «Площадь ≤ 50?» — это предикат внутренней вершины.

**«Лист»**

**Лист** — **конечная** вершина. У неё **нет детей**. Здесь дерево **останавливается** и даёт **ответ**.

**Что приписано:** прогноз $c_v$ — **число** (регрессия), **класс** (классификация) или **вектор вероятностей**.

**Пример:** «5 млн» — это прогноз листа.

Пример на графике:

```text
              [x1 ≤ 0.5?]           ← внутренняя вершина, предикат β₁
             /            \
      [x2 ≤ 0.3?]        [x2 ≤ 0.7?]  ← внутренние вершины, предикаты β₂, β₃
       /      \            /      \
    класс1  класс2     класс3  класс4  ← листья, прогнозы c₁...c₄
```

**Самый частый предикат на практике:**

$$
\beta_{j,t}(x) = [x_j \le t]
$$

- $j$ — номер признака
- $t$ — порог

Объект идёт вправо, если $x_j \le t$, влево — если $x_j > t$ (как в статье; в разных библиотеках направление может отличаться, идея та же).

---

### 1.3. Важные свойства (запомни)

1. **Производная = 0** почти везде → **градиентный спуск не подходит**.
2. Дерево **не экстраполирует**: за границами обучающих данных предсказание — константа листа.
3. Дерево **чемпион переобучения**: можно сделать лист на каждый объект → идеальный train, плохой test.
4. Поэтому нужно **ограничивать сложность** дерева (глубина, размер листа…).

**Аналогия:** дерево без ограничений — студент, который выучил ответы к билетам наизусть, а не предмет.

Ниже, разъяснение пунктов

**Свойство 1. Производная = 0 почти везде → градиентный спуск не подходит**

**Что это значит**

Дерево — **ступенчатая** функция. Она **не меняется** плавно. Внутри листа — **константа**. На границе — **резкий скачок**.

**Производная** (скорость изменения) внутри листа = **0**. На границе — **не определена** (разрыв).

**Градиентный спуск** работает так:

$$
w \leftarrow w - \mathrm{lr} \cdot \frac{\partial L}{\partial w}
$$

Он **требует**, чтобы производная **существовала** и была **не нулевой**. У дерева её **нет**.

**Почему это важно**

**Нельзя** обучить дерево так же, как линейную модель или нейросеть. **Нет градиента** → **нет SGD**.

**Что используют вместо**

**Жадный алгоритм** — перебор сплитов и выбор лучшего. Об этом — Часть 3.

**Аналогия**

Ты **не можешь** «плавно» переставить ступеньки лестницы. Ты **переставляешь** их **целиком**. Дерево — **лестница**, а не **наклонная плоскость**.

---

**Свойство 2. Дерево не экстраполирует**

**Что это значит**

За границами **обучающих данных** предсказание — **константа** последнего листа.

**Пример:** модель видела квартиры **до 200 м²**. Приходит **300 м²**.

- Дерево **не может** сказать «дороже 200-метровой».
- Оно **не знает**, что за 200.
- Ответ — **тот же**, что для 200 м².

**Сравни с линейной регрессией**

| **Модель** | **Что делает за границами** |
|----|----|
| **Линейная регрессия** | **Продолжает** прямую → может экстраполировать |
| **Дерево** | **Останавливается** → константа |

**Пример:** линейная модель $y = 2 + 0.1x$:

- $x = 200$ → $y = 22$.
- $x = 300$ → $y = 32$ (продолжила прямую).

**Дерево:**

- $x = 200$ → лист «22».
- $x = 300$ → тот же лист «22».

**Почему так**

Дерево **не строит** формулу. Оно **запоминает** области. За пределами train — **новая** область, но дерево **не знает**, что туда положить → **константа** ближайшего листа.

**Аналогия**

Ты **выучил** цены на квартиры **до 200 м²**. Тебя спрашивают про **300 м²**. Ты **не знаешь** — говоришь «как 200». **Не потому что так правильно**, а потому что **больше нечего** сказать.

---

**Свойство 3. Дерево — чемпион переобучения**

**Что это значит**

Можно построить дерево, где **каждый объект** — отдельный лист. Тогда:

- **Train** — **идеально** (0 ошибок).
- **Test** — **плохо** (модель запомнила, не обобщила).

**Пример**

**100 объектов** → **100 листьев**. В каждом — **один** объект. Дерево **запомнило** все ответы.

**На train:** идеально. **На test:** новый объект → попадает в **один** из листьев → получает ответ **того** объекта, который там был. **Случайно**.

**Аналогия**

**Студент вызубрил** ответы к каждому билету. На этих билетах — **5**. На **новых** — **2**.

**Дерево так же:** запомнило train, но **не поняло** закономерность.

**Почему так**

Дерево **очень гибкое**. Оно **может** подстроиться под **любые** данные. Если **не ограничивать** — оно **запомнит** шум.

---

**Свойство 4. Нужно ограничивать сложность**

**Что ограничивают**

| **Параметр** | **Что делает** |
|----|----|
| `max_depth` | Максимальная глубина |
| `min_samples_leaf` | Минимум объектов в листе |
| `max_leaf_nodes` | Максимум листьев |

**Идея:** не даём дереву **разрастись** до листа на каждый объект.

**Аналогия**

Студенту **не дают** вызубрить **все** билеты. Говорят: «Учи **только** главное. Не больше **10** страниц конспекта». Тогда он **поймёт** суть, а не **запомнит** ответы.

**Что это даёт**

- **Train** — **чуть хуже** (не 100%, а 95%).
- **Test** — **лучше** (модель **обобщает**, а не **запоминает**).

**Компромисс:** чуть меньше точности на train → **сильно** больше на test.

---

### 1.4. Классификация vs регрессия (картинка в голове)

| Задача | Что в листе | Как выглядит поверхность |
|:---|:---|:---|
| **Классификация** | класс или вероятности | прямоугольные области разных классов |
| **Регрессия** | константа (среднее / медиана) | **ступеньки** (кусочно-постоянная функция) |

Без ограничения глубины ступеньки «мечутся» между точками train. С ограничением глубины — грубее, но обобщает лучше.

**Разбор: что общего и что разное**

**Общее:** обе задачи используют **одну и ту же структуру** — дерево с предикатами и листьями.

**Разное:** то, **что записывается в лист** и **как измеряется качество**.

---

**1. Классификация**

**Что в листе**

**Два варианта:**

| **Вариант** | **Что в листе** | **Пример** |
|----|----|----|
| **Класс** | Одно значение — самый частый класс | «кошка» |
| **Вероятности** | Вектор долей классов | [0.8, 0.15, 0.05] |

**Пример с классом:** В лист попали объекты: 8 кошек, 2 собаки → самый частый — **кошка**. Лист выдаёт «кошка».

**Пример с вероятностями:** Те же 8 кошек, 2 собаки → вероятности **[0.8, 0.2]**. Лист выдаёт вектор.

**Зачем вероятности:** нужна **уверенность**, а не только класс. Например, для **порога** (если P > 0.7 → «кошка»).

**Как выглядит поверхность**

Пространство разбито на **прямоугольники**. В каждом — **один класс** (или вектор вероятностей).

```text
x2
 ↑
 |  ┌─────────┬─────────┐
 |  │  кошка  │  собака │
 |  ├─────────┼─────────┤
 |  │  кошка  │  собака │
 |  └─────────┴─────────┘
 +──────────────────────→ x1
```

**Границы** между классами — **ступенчатые**. Не плавные.

---

**2. Регрессия**

**Что в листе**

**Константа** — одно число. Обычно **среднее** (для MSE) или **медиана** (для MAE).

**Пример:** в лист попали квартиры с ценами 5, 6, 7 млн → среднее **6 млн**. Лист выдаёт **6 млн**.

**Как выглядит поверхность**

**Ступеньки.** Каждый прямоугольник — **одна высота**.

```text
Цена
 ↑
 |           ┌──────┐
 |           │  9   │
 |           └──────┘
 |
 |  ┌──────┐
 |  │  5   │
 |  └──────┘
 +──────────────────→ Площадь
```

**Не плавная кривая**, а **лестница**.

---

**3. Что значит «ступеньки мечутся между точками train»**

**Без ограничения глубины**

Дерево **разрастается** до листа на каждый объект. Тогда:

- Каждая **точка** train — **свой** лист.
- Поверхность — **много мелких** ступенек.
- Каждая ступенька **подстроена** под **один** объект.
- **Между** точками — **случайные** переходы.

**Пример:** 100 точек train → 100 листьев → **100 мелких** ступенек. На **новых** данных — **плохо**.

**С ограничением глубины**

Дерево **останавливается** раньше. Тогда:

- **Мало** листьев → **крупные** ступеньки.
- Каждая ступенька — **группа** объектов.
- Поверхность **гладкая** (в смысле «крупных блоков»).

**Пример:** глубина 3 → 8 листьев → **8 крупных** ступенек. На **новых** данных — **лучше**.

---

**4. Сравнительная таблица**

|    | **Классификация** | **Регрессия** |
|----|----|----|
| **Что в листе** | Класс или вероятности | Число (среднее / медиана) |
| **Поверхность** | Прямоугольники классов | Ступеньки |
| **Критерий** | Джини / энтропия / misclassification | MSE / MAE |
| **Оптимальный ответ** | Самый частый класс | Среднее / медиана |

---

**5. Аналогия: мозаика**

**Классификация** — мозаика из **цветных** плиток. Каждая плитка — **один цвет** (класс).

**Регрессия** — мозаика из **плиток разной высоты**. Каждая — **одна высота** (число).

**Общее:** и там, и там — **прямоугольные** области. Внутри — **константа**.

---

**6. Почему это важно для практики**

| **Задача** | **Что выбрать** |
|----|----|
| **Классификация** | Дерево с критерием **Джини** или **энтропия** |
| **Регрессия** | Дерево с критерием **MSE** (или MAE) |

## 2. Решающий пень (дерево глубины 1)

**Что это**

**Решающий пень** — дерево **глубины 1**. То есть **один вопрос** и **два листа**.

```text
        [x_j ≤ t?]
        /        \
     Да          Нет
     /             \
  Лист 1        Лист 2
```

**Простыми словами:** пень — это **самое простое** дерево. Один вопрос — два ответа.

**Почему «пень»:** дерево **не растёт** дальше. Только «ствол» (корень) — без веток. Как **пень** от спиленного дерева.

---

**Как пень делает предсказание**

**Пример:** предсказываем цену квартиры.

**Пень:** «Площадь ≤ 50?»

- **Да** → лист «5 млн» (для маленьких квартир).
- **Нет** → лист «10 млн» (для больших).

**Приходит квартира 40 м²:**

- «Площадь ≤ 50?» → **Да** → **5 млн**.

**Приходит квартира 60 м²:**

- «Площадь ≤ 50?» → **Нет** → **10 млн**.

**Просто:** один вопрос — ответ.

---

**Сколько возможно пней**

**Пень** = выбор **признака** $j$ и **порога** $t$.

| **Что** | **Сколько вариантов** |
|----|----|
| **Признак** $j$ | $D$ (число признаков) |
| **Порог** $t$ | не больше $N$ «интересных» значений |

**Что значит «интересные» пороги:** пороги, которые **что-то меняют**. Если между двумя соседними объектами порог **не меняет** ответ — он **не нужен**.

**Итого:** не больше $O(N \cdot D)$ возможных пней.

**Пример:** 1000 объектов, 10 признаков → до **10 000** пней.

---

**Как выбирают лучший пень**

**Наивный перебор:**

```text
для каждого признака j:          ← D признаков
    для каждого порога t:        ← N порогов
        посчитать loss на всей выборке    ← N объектов
        запомнить лучший (j, t)
```

**Что происходит:**

1. Берём **признак** $j$ (например, площадь).
2. Берём **порог** $t$ (например, 50).
3. Делим объекты на две группы: «≤ 50» и «> 50».
4. Считаем **loss** (ошибку) — насколько хорошо разделилось.
5. Запоминаем **лучший** $(j, t)$.

**Повторяем** для всех $j$ и $t$ → находим **лучший** пень.

---

**Сложность наивного перебора**

**Считаем операции:**

- $D$ признаков.
- $N$ порогов на признак.
- $N$ объектов — чтобы посчитать loss.

**Итого:** $D \cdot N \cdot N = O(N^2 D)$.

**Пример:** 1000 объектов, 10 признаков → $10^3 \cdot 10^3 \cdot 10 = 10^7$ операций. **Много**, но выполнимо.

**Но** это **только один** пень. А дерево — **много** пней. Об этом — §3.

---

**Аналогия: выбор лучшего вопроса**

Ты в игре «20 вопросов». Хочешь задать **самый лучший** вопрос первым.

**Перебираешь:**

- «Это живое?» → плохо разделило.
- «Это больше метра?» → плохо.
- «Это летает?» → хорошо.

**Выбираешь** лучший. Пень — это **один** такой вопрос.

---

## 3. Дерево произвольной глубины

**Идея: рекурсивно искать пень в каждой ветке**

**Что делают:**

1. Находим **лучший пень** для **всей** выборки.
2. Делим данные на **две** группы.
3. Для **каждой** группы **снова** ищем лучший пень.
4. Делим **каждую** группу ещё на две.
5. **Повторяем**, пока не остановимся.

**Что получится:** **большое** дерево. Если не останавливаться — оно **запомнит всю выборку** (лист на каждый объект).

---

**Что хочется: оптимальное дерево**

**Оптимальное дерево** — дерево **минимальной глубины**, которое **идеально** разделяет данные.

**Пример:** 100 объектов. Хочется дерево, которое:

- **все** 100 разделит **правильно**;
- **как можно короче** (меньше вопросов).

**Кажется:** можно просто **перебрать** все деревья и выбрать лучшее.

---

**Почему это невозможно**

**Число возможных деревьев — астрономическое.**

**Считаем:**

- Для одного пня — до $N \cdot D$ вариантов.
- Для дерева глубины 2 — $(N \cdot D)^2$.
- Для глубины $H$ — $(N \cdot D)^H$.

**Пример:** $N = 1000$, $D = 10$, $H = 10$:

$$
(10\,000)^{10} = 10^{40}
$$

**Это больше, чем атомов в наблюдаемой Вселенной** (≈ $10^{80}$ — но $10^{40}$ тоже **непереборно**).

**Перебрать все** — **невозможно** за время жизни Вселенной.

---

**Это называется NP-полная задача**

**NP-полная** — значит: **точный оптимум** можно найти, но за **экспоненциальное время**. Для реальных данных — **неприемлемо**.

**Что это значит на практике:** **не существует** известного **быстрого** алгоритма, который **гарантированно** найдёт **оптимальное** дерево.

**Аналогия:** кратчайший маршрут по 100 городам. Перебрать **все** маршруты — $100!$ вариантов. Больше, чем атомов во Вселенной. **Невозможно** перебрать.

---

**Что делают на практике**

Вместо **точного** оптимума — **два подхода**:

**1. Жадный алгоритм**

**Идея:** на каждом шаге ищем **лучший сплит** — **не думая о будущем**.

**Плюс:** работает **быстро**. **Минус:** может **не найти** идеальное дерево.

**Аналогия:** собираешь рюкзак. **Жадно** берёшь **самый ценный** предмет. Потом **следующий** по ценности. Не думаешь о комбинациях. Получаешь **хороший** рюкзак, но **не оптимальный**.

**2. Ускорение перебора**

**Идеи из computer science:**

- **Динамическое программирование** — сортировка + накопление статистик.
- **Гистограммы** — дискретизация признаков.

**Что дают:** уменьшают сложность с $O(N^2)$ до $O(N \log N)$ и лучше.

**Об этом** — Часть 7.

---

**Схема: от «хочу оптимальное» к «делаю жадное»**

```text
Хочу: оптимальное дерево минимальной глубины
        │
        ▼
Проблема: NP-полная задача → экспоненциальное время
        │
        ▼
Что делаю: жадный алгоритм (быстро, но не оптимум)
        │
        ▼
Дополнительно: ускорение перебора (динамика, гистограммы)
```

---

**Ключевая мысль: жадность ≠ оптимум**

**Жадный алгоритм** выбирает **лучший сплит сейчас** — но это **не значит**, что дерево **в целом** будет оптимальным.

**Пример (XOR):** данные, которые **нельзя** разделить **одним** вопросом. Жадный алгоритм может **застрять** — выбрать сплит, который **кажется** хорошим, но **мешает** дальнейшему разделению.

**Об этом** — §11.

# ЧАСТЬ 3. ЖАДНЫЙ АЛГОРИТМ

---

## **Что это**

**Жадный алгоритм** — способ **построить дерево шаг за шагом**, выбирая на каждом шаге **лучший вопрос прямо сейчас**, не думая о будущем.

**Простыми словами:** мы **не ищем** идеальное дерево (это слишком долго). Мы строим **хорошее** — по шагам.

---

## **Общая схема (4 шага)**

Конспект даёт такую схему. Пусть $R$ — объекты в **текущем узле** (в начале — **вся** выборка).

### **Шаг 1. Создаём вершину**

Берём **текущий** узел. В начале — **корень** (вся выборка).

### **Шаг 2. Проверяем критерий остановки**

**Критерий остановки** — условия, когда дерево **останавливается** и делает **лист**:

- объекты в узле **уже одинаковые** (все одного класса / близкие цены);
- объектов **слишком мало**;
- достигнута **максимальная глубина**.

**Если** критерий выполнен → **лист**, ставим ответ, **стоп**. **Иначе** → идём к шагу 3.

### **Шаг 3. Ищем лучший сплит**

**Перебираем** все возможные вопросы (предикаты) и выбираем **лучший** — тот, который **лучше всего разделяет** данные.

**Как измеряется «лучше»:** через **критерий ветвления** (Gain, impurity). Об этом — Часть 4.

### **Шаг 4. Делим и повторяем**

- **Делим** объекты узла на **две группы** (по выбранному вопросу).
- Для **каждой** группы **рекурсивно** повторяем с шага 1.

---

## **Схема на картинке**

```text
        Шаг 1: создали корень (вся выборка)
              │
        Шаг 2: стоп? Нет
              │
        Шаг 3: лучший сплит → "Площадь > 50?"
              │
        Шаг 4: делим на две группы
              │
        ┌─────┴─────┐
        │           │
    Группа A    Группа B
        │           │
    Шаг 1:      Шаг 1:
    создали     создали
    узел        узел
        │           │
    Шаг 2:      Шаг 2:
    стоп?       стоп?
    ...         ...
```

**Что происходит:** дерево **растёт** — каждый узел делится на два, пока не сработает остановка.

---

## **Пример: предсказание цены квартиры**

**Данные:** 8 квартир.

| **Площадь** | **Этаж** | **Цена** |
|----|----|----|
| 30 | 2 | 4 млн |
| 35 | 3 | 4.5 млн |
| 40 | 4 | 5 млн |
| 45 | 5 | 5.5 млн |
| 60 | 6 | 8 млн |
| 70 | 7 | 9 млн |
| 80 | 8 | 10 млн |
| 90 | 9 | 11 млн |

### **Шаг 1: корень (все 8 квартир)**

### **Шаг 2: стоп? Нет — квартиры разные.**

### **Шаг 3: ищем лучший сплит**

**Перебираем вопросы:**

- «Площадь > 50?» → 4 маленькие / 4 большие.
- «Этаж > 5?» → 4 низкие / 4 высокие.
- ...

**Лучший** — «Площадь > 50?». Потому что **цены** в группах **сильно различаются**:

- Маленькие: 4–5.5 млн.
- Большие: 8–11 млн.

### **Шаг 4: делим**

```text
              [Площадь > 50?]
             /              \
           Нет              Да
           /                  \
    4 квартиры           4 квартиры
    (4–5.5 млн)          (8–11 млн)
```

### **Повторяем для каждой группы**

**Левая группа** (маленькие):

- Шаг 2: стоп? Нет.
- Шаг 3: лучший сплит — например, «Площадь > 37?».
- Шаг 4: делим на «30–35» и «40–45».

**Правая группа** (большие):

- Аналогично.

**И так далее**, пока не остановимся.

---

## **Что предсказывать в листе**

Когда дерево **остановилось** — в листе **один ответ**.

| **Задача** | **Что в листе** | **Пример** |
|----|----|----|
| **Классификация** | Самый частый класс или вероятности | «кошка» / [0.8, 0.2] |
| **Регрессия** | Среднее или медиана | 4.75 млн |

**Пример:** в лист попали квартиры 30, 35 м² (цены 4, 4.5 млн). Среднее = **4.25 млн**. Лист выдаёт **4.25 млн**.

**Для классификации:** в лист попали 8 кошек, 2 собаки → самый частый — **кошка**.

---

## **Критерий остановки — подробнее**

Дерево **останавливается**, когда:

| **Условие** | **Что значит** |
|----|----|
| **Объекты одинаковые** | Все одного класса / цены близки |
| **Мало объектов** | 1–2 объекта — делить нечего |
| **Достигнута глубина** | `max_depth` сработал |
| **Сплит не улучшает** | Все вопросы дают **тот же** результат |

**Пример:** в узле 1 объект → **лист** (делить нечего).

**Пример:** в узле 5 кошек → **лист** «кошка» (все одинаковые).

---

## **Почему алгоритм называется жадным**

**Жадный** — потому что на **каждом** шаге мы берём **лучшее прямо сейчас**, не думая о **последствиях**.

**Пример:** на шаге 3 выбрали «Площадь > 50?». Может, **другой** вопрос дал бы **лучшее дерево** в **целом**. Но мы **не проверяем** — берём **лучший сейчас**.

**Аналогия:** ты собираешь рюкзак. **Жадно** берёшь **самый ценный** предмет. Потом **следующий**. Не думаешь о комбинациях.

**Результат:** **хороший** рюкзак, но **не обязательно** идеальный.

---

## **Рекурсия: что это**

**Рекурсия** — когда функция **вызывает саму себя**.

**Пример:**

```text
функция построить_дерево(объекты):
    если стоп → вернуть лист
    найти лучший сплит
    разделить на левые и правые
    левое_поддерево = построить_дерево(левые)   ← вызов себя
    правое_поддерево = построить_дерево(правые) ← вызов себя
    вернуть узел с поддеревьями
```

**Что происходит:** функция **вызывает себя** для **каждой** группы. Группы делятся дальше — и так до остановки.

**Аналогия:** матрёшка. Открываешь большую — внутри **меньшая**. Открываешь её — внутри **ещё меньше**. И так до **самой маленькой**.

---

## **Полная картина**

```text
1. Создаём корень (все объекты)
        │
2. Стоп?
   ├── Да → лист, ответ
   └── Нет → идём дальше
        │
3. Ищем лучший сплит
        │
4. Делим на две группы
        │
   ┌────┴────┐
   │         │
Группа A  Группа B
   │         │
   └── повторяем с шага 1 для каждой
```

**Итог:** дерево **растёт**, пока не остановится.

# ЧАСТЬ 4. КРИТЕРИИ ВЕТВЛЕНИЯ (IMPURITY)

## **Что это и зачем**

Когда дерево ищет **лучший вопрос** (сплит), оно должно **как-то сравнивать** варианты. Для этого нужен **критерий** — число, которое говорит «этот сплит хороший, а этот плохой».

**Два ключевых понятия:**

| **Понятие** | **Что значит** | **Аналогия** |
|----|----|----|
| **Impurity** (загрязнённость) | Насколько **перемешаны** классы в узле | «Насколько грязная вода» |
| **Gain** (выигрыш) | Насколько сплит **уменьшил** impurity | «Насколько вода стала чище» |

**Чем меньше impurity — тем лучше.** Чем больше Gain — тем лучше сплит.

---

## **§5. Общая идея: информативность**

### **Что такое impurity**

**Impurity** узла $R$ — это **мера неоднородности** объектов в нём.

- Если в узле **все объекты одного класса** → impurity = **0** (идеально чисто).
- Если классы **поровну** → impurity **максимальна** (полная неразбериха).

**Формула из конспекта:**

$$
H(R) = \min_c \frac{1}{|R|} \sum_{x_i \in R} L(y_i, c)
$$

**Разберём по частям:**

| **Часть** | **Что значит** |
|----|----|
| $L(y_i, c)$ | **Ошибка** предсказания $c$ для объекта $y_i$ |
| $\frac{1}{\lvert R \rvert}\sum$ | **Средняя** ошибка по всем объектам узла |
| $\min_c$ | Берём **лучшую** константу $c$ (которая даёт минимум) |

**Простыми словами:** impurity — это **минимальная средняя ошибка**, если предсказывать **одной константой** для всего узла.

**Пример:** в узле 5 кошек, 5 собак. Лучшая константа — «кошка» (или «собака»). Ошибка = 50%. Impurity = **0.5**.

---

### **Impurity пня (двух листьев)**

Если сплит разделил узел $R$ на $R_\ell$ и $R_r$, то **общая** impurity:

$$
H(R_\ell, R_r) = \frac{|R_\ell|}{|R|} H(R_\ell) + \frac{|R_r|}{|R|} H(R_r)
$$

**Простыми словами:** берём impurity **каждого** ребёнка и **усредняем** с **весами** (по размеру).

**Пример:**

- Левый ребёнок: 4 объекта, impurity = 0.
- Правый ребёнок: 6 объектов, impurity = 0.5.
- Всего 10 объектов.

$$
H = \frac{4}{10} \cdot 0 + \frac{6}{10} \cdot 0.5 = 0.3
$$

---

### **Критерий ветвления ($\text{Branch}$)**

В статье сравнивают не сами impurity, а **информативность всего пня** — среднюю потерю по двум его листьям:

$$
H(R_\ell, R_r) = \frac{1}{|R|}\Big( \sum_{x_i \in R_\ell} L(y_i, c_\ell) + \sum_{x_i \in R_r} L(y_i, c_r) \Big)
$$

где $c_\ell$ и $c_r$ — **оптимальные** константы для левого и правого листа (то есть $H(R_\ell)$ и $H(R_r)$ в наших обозначениях).

Сравнивать сплиты удобно через **разность** информативностей родителя и пня. В статье её умножают на $|R|$ «для симметрии» и получают **критерий ветвления**:

$$
\text{Branch}(R, j, t) = |R| \cdot H(R) - |R_\ell| \cdot H(R_\ell) - |R_r| \cdot H(R_r)
$$

**Свойства:**

- $\text{Branch} \ge 0$ — разделив объекты на две кучки и подобрав ответ каждой, **хуже не сделаешь**;
- чем **больше** $\text{Branch}$, тем **лучше** сплит;
- выбор сплита по $\text{Branch}$ **совпадает** с выбором по Gain (отличие — только в множителе $|R|$, одинаковом для всех сплитов в узле).

### **Gain** — насколько сплит **улучшил** ситуацию

**Gain** — это **разница** между impurity узла и impurity получившегося пня:

$$
Gain(R, R_\ell, R_r) = H(R) - H(R_\ell, R_r)
= H(R) - \frac{|R_\ell|}{|R|} H(R_\ell) - \frac{|R_r|}{|R|} H(R_r)
$$

**Простыми словами:** было $H(R)$ — стало $H(R_\ell, R_r)$. Разница — **выигрыш**.

- **Чем больше Gain — тем лучше сплит.**
- Худший случай: $Gain = 0$ — сплит **ничего не улучшил**.
- Отрицательным Gain быть **не может** (см. ниже).
- Между Gain и $\text{Branch}$ простая связь: $Gain = \text{Branch} / |R|$.

---

### **Числовой пример: бесполезный сплит**

В узле **10 объектов**: 6 кошек и 4 собаки. Пусть impurity — доля ошибок при предсказании самого частого класса:

$$
H(R) = 1 - \max(p_{\text{кошка}}, p_{\text{собака}}) = 1 - 0.6 = 0.4
$$

Пробуем сплит «любит рыбу?»:

| **Ветка** | **Состав** | **Impurity** |
|----|----|----|
| Слева | 3 кошки, 1 собака | $1 - 0.75 = 0.25$ |
| Справа | 3 кошки, 3 собаки | $1 - 0.5 = 0.5$ |

$$
H(R_\ell, R_r) = \frac{4}{10} \cdot 0.25 + \frac{6}{10} \cdot 0.5 = 0.1 + 0.3 = 0.4
$$

$$
Gain = 0.4 - 0.4 = 0
$$

**Вывод:** сплит **бесполезен** — impurity не изменилась. А вот сплит, после которого слева остались только кошки, а справа только собаки, дал бы:

$$
H(R_\ell, R_r) = 0 \quad\Rightarrow\quad Gain = 0.4 - 0 = 0.4
$$

### **Второй пример**

- Было: $H(R) = 0.5$.
- Стало: $H(R_\ell, R_r) = 0.3$.
- $Gain = 0.5 - 0.3 = 0.2$.

---

### **Зачем всё это: как дерево выбирает лучший сплит**

В каждом узле алгоритм делает **одну** вещь: **перебирает** все возможные сплиты и берёт тот, у которого **Gain максимальный**. Никакой человек не подсказывает — критерий работает как **линейка**.

Проиллюстрируем на нашем узле (6 кошек, 4 собаки, $H(R) = 0.4$):

| **Сплит** | **Слева** | **Справа** | **Impurity пня** | **Gain** |
|:---|:---|:---|:---|:---|
| «Любит рыбу?» | 3 кошки, 1 собака | 3 кошки, 3 собаки | $\tfrac{4}{10}\cdot 0.25 + \tfrac{6}{10}\cdot 0.5 = 0.4$ | **0** |
| «Любит молоко?» | 5 кошек, 1 собака | 1 кошка, 3 собаки | $\tfrac{6}{10}\cdot\tfrac{1}{6} + \tfrac{4}{10}\cdot 0.25 = 0.2$ | **0.2** |

Второй сплит **делает узел чище** (impurity падает с 0.4 до 0.2), хотя и не идеально. Дерево выберет **его**, забракует первый и пойдёт строить следующий уровень уже **внутри** новых листьев.

**Вот ответ на «зачем»:** критерий — это способ **автоматически** сравнивать варианты вопросов и всегда брать **лучший из доступных**. Без него дерево не знало бы, какой вопрос задать первым.

---

### **Почему Gain ≥ 0 всегда**

Разбив объекты на две группы и **подобрав ответ каждой группе отдельно**, мы **не можем сделать хуже**, чем один общий ответ: если новый ответ окажется плохим, можно просто оставить в обоих листьях ту же константу, что была в родителе, и ошибка не вырастет. Значит, минимум по двум листьям **не больше** минимума по родителю.

---

### **Аналогия: сортировка носков**

У тебя **куча носков**: чёрные и белые, **вперемешку** — это **impurity = 0.5** (поровну).

Ты **делишь** кучу на две:

- Слева — **только чёрные**.
- Справа — **только белые**.

**Impurity стала 0.** Gain = 0.5. **Идеальный сплит.**

Если бы ты разделил **плохо** (в обеих кучах всё ещё вперемешку) — Gain был бы **маленький** (в пределе — **0**).

---

## **§6. Регрессия: MSE**

### **Loss = квадрат ошибки**

$$
L(y, c) = (y - c)^2
$$

**Оптимальная константа** в листе — **среднее**:

$$
c^* = \bar{y}_R = \frac{1}{|R|} \sum_{y_i \in R} y_i
$$

**Почему среднее:** среднее **минимизирует** сумму квадратов отклонений. Это математический факт.

### **Impurity = дисперсия**

$$
H_{\text{MSE}}(R) = \frac{1}{|R|} \sum_{y_i \in R} (y_i - \bar{y}_R)^2
$$

**Простыми словами:** impurity — это **дисперсия** цен в узле. Насколько цены **разбросаны** вокруг среднего.

- Цены близки → дисперсия **маленькая** → impurity **маленькая**.
- Цены сильно разные → дисперсия **большая** → impurity **большая**.

### **Правило выбора сплита**

**Выбирай сплит так, чтобы взвешенная сумма дисперсий в листьях была минимальна.**

**Пример:**

| **Сплит** | **Дисперсия слева** | **Дисперсия справа** | **Взвешенная сумма** |
|----|----|----|----|
| A | 0.5 | 0.5 | 0.5 |
| B | 0.1 | 0.9 | 0.5 |
| C | 0.2 | 0.2 | **0.2** ← лучше |

**Сплит C** лучше — потому что **обе** группы **однородные**.

**Аналогия:** «режем так, чтобы в каждой половинке ответы были похожи друг на друга».

### **Числовой пример: 8 квартир**

Вернёмся к таблице из Части 3 (площадь / цена):

| **Площадь** | 30 | 35 | 40 | 45 | 60 | 70 | 80 | 90 |
|----|----|----|----|----|----|----|----|----|
| **Цена, млн** | 4 | 4.5 | 5 | 5.5 | 8 | 9 | 10 | 11 |

**Impurity корня** (дисперсия всех цен):

$$
\bar{y} = \frac{4 + 4.5 + 5 + 5.5 + 8 + 9 + 10 + 11}{8} = 7.125
$$

$$
H(R) = \frac{1}{8}\sum (y_i - 7.125)^2 \approx 6.42
$$

**Пробуем сплит «Площадь > 50?»:**

| **Ветка** | **Цены** | **Среднее** | **Дисперсия** |
|----|----|----|----|
| Слева (≤ 50) | 4, 4.5, 5, 5.5 | 4.75 | 0.3125 |
| Справа (> 50) | 8, 9, 10, 11 | 9.5 | 1.25 |

$$
H(R_\ell, R_r) = \frac{4}{8}\cdot 0.3125 + \frac{4}{8}\cdot 1.25 = 0.78125
$$

$$
Gain = 6.42 - 0.78 \approx 5.64
$$

**Сравним с плохим сплитом «Площадь > 85?»:** слева 7 квартир (дисперсия ≈ 4.89), справа 1 (дисперсия 0):

$$
H(R_\ell, R_r) = \frac{7}{8}\cdot 4.89 + \frac{1}{8}\cdot 0 \approx 4.28
\quad\Rightarrow\quad Gain \approx 6.42 - 4.28 = 2.14
$$

**Вывод:** сплит «> 50» лучше (**Gain 5.64 против 2.14**) — он делит цены на две **однородные** группы.

## **§7. Регрессия: MAE**

### **Loss = модуль ошибки**

$$
L(y, c) = |y - c|
$$

**Оптимальная константа** — **медиана**.

### **Impurity = среднее абсолютное отклонение от медианы**

$$
H_{\text{MAE}}(R) = \frac{1}{|R|} \sum_{y_i \in R} |y_i - \mathrm{median}(R)|
$$

**Простыми словами:** то же, что MSE, но **без квадрата**. Менее чувствительно к **выбросам**.

**Когда использовать MAE:** если в данных есть **выбросы** (аномально дорогие квартиры), MAE **устойчивее**.

### **Числовой пример: те же 8 квартир**

Цены: 4; 4.5; 5; 5.5; 8; 9; 10; 11. Медиана — среднее двух центральных значений (5.5 и 8):

$$
\mathrm{median} = \frac{5.5 + 8}{2} = 6.75
$$

$$
H_{\text{MAE}}(R) = \frac{0.75 + 2.25 + 1.75 + 1.25 + 1.25 + 2.25 + 3.25 + 4.25}{8} = \frac{19}{8} = 2.375
$$

**Сплит «Площадь > 50?»:**

| **Ветка** | **Цены** | **Медиана** | **MAE** |
|----|----|----|----|
| Слева | 4, 4.5, 5, 5.5 | 4.75 | $2/4 = 0.5$ |
| Справа | 8, 9, 10, 11 | 9.5 | $4/4 = 1$ |

$$
H(R_\ell, R_r) = \frac{4}{8}\cdot 0.5 + \frac{4}{8}\cdot 1 = 0.75
\quad\Rightarrow\quad Gain = 2.375 - 0.75 = 1.625
$$

Сравни с MSE-примером выше: там те же данные дали средние 4.75 / 9.5 — как видишь, для симметричных данных разница MAE и MSE невелика. А вот **один выброс** (цена 100 млн) почти не сдвинет медиану (и MAE-сплит), зато сильно раздует среднее и дисперсию.

## **§8. Классификация: misclassification error**

### **Что это**

**Доля ошибок**, если предсказывать **самый частый** класс.

Пусть $p_k$ — **доля** класса $k$ в узле:

$$
H_{\text{err}}(R) = 1 - \max_k p_k
$$

**Пример:** классы 70% / 30%.

- Самый частый — 70%.
- Impurity = $1 - 0.7 = 0.3$.

**Простыми словами:** если предсказать «самый частый класс», ошибёмся на **30%** объектов.

### **Минус этого критерия**

**Слишком грубый.** Не различает **разные** ситуации с одинаковым максимумом.

**Пример:**

- Узел A: 70% кошек, 30% собак → impurity = 0.3.
- Узел B: 70% кошек, 15% собак, 15% птиц → impurity = 0.3.

**Impurity одинаковая**, хотя узлы **разные**. Поэтому на практике чаще используют **энтропию** или **Джини**.

### **Ещё пример: критерий «слепнет» на двух разных сплитах**

В узле **800 объектов**: 400 кошек и 400 собак ($p = 0.5/0.5$):

$$
H(R) = 1 - 0.5 = 0.5
$$

**Сплит A** (делит примерно поровну): слева 300/100, справа 100/300.

$$
H(R_\ell, R_r) = \frac{1}{2}\cdot 0.25 + \frac{1}{2}\cdot 0.25 = 0.25
\quad\Rightarrow\quad Gain = 0.25
$$

**Сплит B** (создаёт **чистый** лист): слева 200/400, справа 200/0.

- веса веток: $600/800 = 0.75$ и $200/800 = 0.25$;
- слева $p_{\max} = 400/600 = 2/3$ → impurity $= 1/3$;
- справа impurity $= 0$ (только кошки).

$$
H(R_\ell, R_r) = 0.75\cdot \frac{1}{3} + 0.25 \cdot 0 = 0.25
\quad\Rightarrow\quad Gain = 0.25
$$

**Итог: Gain одинаковый**, хотя сплит B явно **лучше** — он отрезал целую чистую ветку. Именно поэтому misclassification error плохо подходит для выбора сплита.

Для сравнения — тот же пример по критерию **Джини**:

| **Сплит** | **Impurity пня** | **Gain** |
|:---|:---|:---|
| A | $0.5 \cdot 0.375 + 0.5 \cdot 0.375 = 0.375$ | 0.125 |
| B | $0.75 \cdot 0.444 + 0.25 \cdot 0 = 0.333$ | **0.167** ← лучше |

**(корневой Джини** $= 1 - (0.5^2 + 0.5^2) = 0.5$**)**. Теперь критерий различает сплиты и выбирает B.

## **§9. Классификация: энтропия**

### **Что это**

**Энтропия Шеннона** — мера **неопределённости**.

$$
H_{\text{ent}}(R) = -\sum_{k=1}^{K} p_k \log p_k
$$

**Простыми словами:** «насколько непредсказуем класс в этом узле».

| **Ситуация** | **Энтропия** |
|----|----|
| Один класс (100%) | **0** — полная определённость |
| Равномерно по $K$ классам | $\log K$ — максимум неопределённости |

**Важно:** логарифм берут по основанию 2 — тогда энтропия измеряется в **битах**. В примерах ниже это подразумевается.

**Пример:** два класса поровну (50/50):

$$
H = -0.5 \log 0.5 - 0.5 \log 0.5 = 1
$$

**Пример:** один класс (100%):

$$
H = -1 \log 1 = 0
$$

**Пример:** классы 70% / 30% — «почти определённость», но всё же не она:

$$
H = -0.7\log_2 0.7 - 0.3\log_2 0.3 \approx 0.36 + 0.52 = 0.88
$$

**Сравни три узла:**

| **Узел** | **Энтропия** | **Смысл** |
|----|----|----|
| 100% кошки | 0 | полная определённость |
| 70% / 30% | 0.88 | почти уверены |
| 50% / 50% | 1.00 | максимум сомнения |

Энтропия меняется **плавно** и чутко реагирует даже на небольшие изменения долей классов — в отличие от misclassification error, который смотрит только на **максимум** (для 70/30 он даёт сразу 0.3, ничего не говоря о «форме» распределения).

**Пример со сплитом:** узел 50/50 ($H = 1$). Сплит дал слева 100% кошек, справа 50/50:

$$
H(R_\ell, R_r) = \frac{4}{8}\cdot 0 + \frac{4}{8}\cdot 1 = 0.5
\quad\Rightarrow\quad Gain = 1 - 0.5 = 0.5
$$

### **Как работает**

**Было поровну** → энтропия **высокая**.

**Сплит разделил** почти идеально → в листьях энтропия **≈ 0** → **Gain большой**.

**Аналогия:** **лотерея**. Если исход **неизвестен** — энтропия **высокая**. Если **знаешь** результат — энтропия **0**.

---

## **§10. Классификация: критерий Джини**

### **Что это**

**Критерий Джини** — ещё одна мера **неоднородности**.

$$
H_{\text{Gini}}(R) = 1 - \sum_{k=1}^{K} p_k^2
$$

**Интерпретация:** ожидаемая доля ошибок, если метки классу присваивать **случайно** с вероятностями $p_k$.

| **Ситуация** | **Джини** |
|----|----|
| Один класс | 0 |
| Два класса 70/30 | $1 - (0.7^2 + 0.3^2) = 0.42$ |
| Два класса 50/50 | $1 - (0.5^2 + 0.5^2) = 0.5$ |

**Сравни с энтропией:** для тех же 70/30 Джини даёт **0.42**, энтропия — **0.88**. Числа разные, но обе меры **одинаково упорядочивают** узлы: от «чисто» к «неразбериха». Поэтому на практике деревья на энтропии и на Джини дают почти одинаковый результат.

### **Числовой пример**

Узел: 2 класса, 4 объекта: `[A, A, B, B]`

→ $p_A = p_B = 0.5$

$$
H = 1 - (0.5^2 + 0.5^2) = 0.5
$$

**Сплит:** слева `[A, A]`, справа `[B, B]`

- $H_\ell = 0$, $H_r = 0$.
- $H_{\text{пень}} = 0$.
- **Gain** = $0.5 - 0 = 0.5$. **Идеальный сплит.**

### **Почему Джини популярен**

- **Быстрее** энтропии (нет логарифма).
- Даёт **похожие** результаты.
- В **sklearn** — **по умолчанию**.

---

## **Итог части 4: какой критерий выбрать**

Все четыре меры отвечают на **один** вопрос — «насколько узел перемешан», — но по-разному. Разница между ними не в «правильности», а в **удобстве для конкретной задачи**:

| **Задача** | **Критерий** | **Почему именно он** |
|:---|:---|:---|
| Регрессия, выбросов мало | **MSE** | оптимальная константа — среднее, дисперсия считается быстро |
| Регрессия, есть выбросы | **MAE** | медиана устойчива: один «сумасшедший» объект не тянет за собой лист |
| Классификация (по умолчанию) | **Джини** | быстро (без логарифма), в `sklearn` стоит по умолчанию |
| Классификация, «по учебнику» | **Энтропия** | понятный информационный смысл — биты неопределённости |
| Классификация | ⚠️ **misclassification** | слишком **грубый**: не различает сплиты (см. §8), для выбора сплита почти не используют |

**Главное, что стоит запомнить:** критерий — это **эвристика для выбора сплитов**, а не сама метрика качества модели. Accuracy / RMSE считаются отдельно, на отложенной выборке, и их результат **не обязан** совпадать с тем, какой критерий использовался при обучении (см. §11).

## **§11. Жадность ≠ оптимум**

### **Что это значит**

Даже с **правильным** критерием жадный алгоритм **не всегда** находит **лучшее** дерево.

### **Пример: XOR**

**XOR** — данные, которые **нельзя** разделить **одним** вопросом:

```text
x2
 ↑
 |  ● ○
 |  ○ ●
 +──────→ x1
```

- «●» — в двух углах **по диагонали**.
- «○» — в двух других.

**Один прямой вопрос** (по $x_1$ или $x_2$) **не разделит** их. Нужно **два** вопроса.

**Разберём на числах.** Четыре точки:

| Объект | $x_1$ | $x_2$ | Класс |
|:---|:---|:---|:---|
| A | 0 | 0 | ● |
| B | 1 | 1 | ● |
| C | 0 | 1 | ○ |
| D | 1 | 0 | ○ |

Возьмём любой сплит по одной оси, например $[x_1 \le 0.5]$:

- слева: A и C — **один ● и один ○**;
- справа: B и D — **один ● и один ○**.

Impurity в обеих ветках $= 0.5$:

$$
H(R_\ell, R_r) = \frac{2}{4}\cdot 0.5 + \frac{2}{4}\cdot 0.5 = 0.5 = H(R)
\quad\Rightarrow\quad Gain = 0
$$

Так же для $[x_2 \le 0.5]$ — в каждой ветке снова 50/50. **Ни один сплит не даёт $Gain > 0$** → жадный алгоритм **вообще не видит**, за что зацепиться на первом шаге.

А ведь задача решается за **два** вопроса:

```text
            [x1 ≤ 0.5?]
            /         \
       Да /           \ Нет
   [x2 ≤ 0.5?]      [x2 ≤ 0.5?]
     /    \            /    \
   C(○)  A(●)        D(○)  B(●)
```

**Вывод:** оптимальное (даже идеальное!) дерево здесь **существует**, но жадный алгоритм его не построит — на первом уровне каждый сплит выглядит бесполезным.

### **Другой пример: критерий ≠ метрика**

Иногда для **MAE-задачи** лучше срабатывает **MSE-критерий** ветвления. И **наоборот**.

**Вывод:** теория «критерий всегда совпадает с метрикой» **не работает**. На практике — **эвристики**.

## 12. Категориальные признаки

Предикат вида «категория ∈ $S$» даёт до $2^{|C|-1} - 1$ сплитов — при большом числе категорий **дорого**.

**Хитрость:** упорядочить категории и работать как с числами:

| Задача | Как упорядочить категории |
|:---|:---|
| Бинарная классификация | по доле положительного класса |
| Регрессия (MSE) | по среднему таргету в категории |

Для энтропии / Джини / MSE такой трюк даёт сплит, **оптимальный среди всех** подмножеств (при указанных критериях).

---

## 13. Пропуски

Одно из удобств деревьев — можно жить с NaN.

**При обучении (выбор сплита по признаку** $j$**):**

- объекты с пропуском $j$ **игнорируем** при переборе порогов;
- после выбора сплита отправляем их в **оба** поддерева с весами $w_\ell = |R_\ell| / (|R_\ell| + |R_r|)$, $w_r = |R_r| / (|R_\ell| + |R_r|)$.

**При применении:**

- объект с пропуском идёт в обе ветки;
- предсказания усредняют с весами $w_\ell$, $w_r$, запомненными при обучении.

**Для категорий:** иногда вводят значение «пропущено» как обычную категорию — полезно, если пропуск **несёт смысл**.

# ЧАСТЬ 6. РЕГУЛЯРИЗАЦИЯ

---

## 14. Как не дать дереву запомнить всё

Обычно комбинируют:

| Ограничение | Смысл |
|:---|:---|
| `max_depth` | максимальная глубина |
| `min_samples_leaf` | минимум объектов в листе |
| `max_leaf_nodes` | максимум листьев |
| min improvement | Gain должен вырасти хотя бы на $\delta$ |

**Два режима:**

| Название | Когда |
|:---|:---|
| **Pre-pruning / early stopping** | проверяем ограничения **во время** роста |
| **Pruning (стрижка)** | сначала вырастили большое дерево, потом обрезали по **отложенной** выборке |

### Стрижка по стоимости (cost-complexity pruning)

«Обрезать по отложенной выборке» — слишком грубо. Есть конкретный критерий: ищем поддерево $T$, которое минимизирует **сумму ошибок листьев плюс штраф за их количество**:

$$
Q_\alpha(T) = \sum_{\text{листья } l} \text{impurity}(l) \cdot |l| + \alpha \cdot |T|
$$

где:

- $\text{impurity}(l) \cdot |l|$ — «стоимость» (суммарная ошибка) листа $l$,
- $|T|$ — число листьев в дереве $T$,
- $\alpha$ — сила штрафа за сложность.

Логика: при $\alpha = 0$ штрафа нет → выгоднее всего самое большое дерево; при росте $\alpha$ выгоднее оставлять меньше листьев. Для каждого $\alpha$ находится своё оптимальное поддерево.

В sklearn это параметр `ccp_alpha`:

```python
DecisionTreeClassifier(ccp_alpha=0.01)
```

- `ccp_alpha=0` — стрижки нет (значение по умолчанию);
- чем больше `ccp_alpha`, тем сильнее дерево обрезается.

**Практический вывод:** `max_depth` и `min_samples_leaf` — это **pre-pruning** (ограничиваем рост), а `ccp_alpha` — это **post-pruning** (обрезаем уже выросшее дерево по формальному критерию).

# ЧАСТЬ 7. УСКОРЕНИЕ АЛГОРИТМА

---

## 15. Наивная сложность

На каждом уровне: перебор сплитов × подсчёт impurity. Грубо для дерева высоты $H$: порядка $O(N^2 D H)$ — доминирует перебор.

---

## 16. Динамическое программирование

Идея: **отсортировать** объекты по признаку и идти слева направо, **накапливая** статистики (сумма, сумма квадратов, counts…).

Для MSE достаточно уметь быстро считать среднее и дисперсию слева/справа.

Сложность выбора сплита в узле с $n$ объектами:

$O(D \cdot n \log n)$ (сортировки) вместо $O(D \cdot n^2)$.

Итого дерево высоты $H$: примерно $O(D N \log N \cdot H)$ — уже намного лучше.

---

## 17. Гистограммный метод

1. Дискретизируем каждый признак на $B$ бинов (примерно равная частота).
2. Перебираем не $N$ порогов, а $B$ границ бинов.
3. Статистики копят в **гистограмме**.

Сложность порядка $O(D N \log N)$ на предобработку + быстрее выбор сплитов ($O(DB)$ на узел вместо $O(Dn)$).

Сплиты чуть грубее, но для жадного дерева это обычно ок. Так работают современные реализации (идеи как в LightGBM и ускоренных деревьях).

---

### 17.1. Мини-пример гистограммы (MSE, идея)

Признак уже отсортирован, дискретизирован в 3 бина.

Считаем для границы «бин 0 vs остальные»:

- слева: count, sum $y$, sum $y^2$ → дисперсия слева
- справа: из полных сумм минус левые → дисперсия справа
- Gain = $H(\text{узел})$ минус взвешенная сумма дисперсий

Перебираем границы бинов, берём max Gain.

---

## 18. Mixed integer optimization (для полноты)

Можно почти точно решить задачу оптимального дерева через **целочисленное программирование** (солверы). На практике для больших данных почти не используют — дорого; жадные деревья + ансамбли выигрывают по скорости.

## 20. Ключевые выводы

 1. Дерево = цепочка порогов $[x_j \le t]$ → кусочно-постоянный ответ
 2. **Нельзя** учить градиентом; строят **жадно**
 3. Оптимальное дерево минимальной глубины — **NP-полное**
 4. Сплит выбирают по **Gain** = снижение impurity
 5. Регрессия: MSE → среднее + дисперсия; MAE → медиана
 6. Классификация: **энтропия** или **Джини** (чаще на практике)
 7. Легко **переобучается** → depth / min_leaf / pruning
 8. Категории: упорядочить по таргету; пропуски: веса в обе ветки
 9. Ускорение: сортировка + динамика, гистограммы
10. Одно дерево — база для **ансамблей**

## 21. Шпаргалка формул

| Что | Формула |
|:---|:---|
| Предикат | $[x_j \le t]$ |
| Impurity узла | $H(R) = \min_c \frac{1}{\lvert R \rvert}\sum L(y_i, c)$ |
| Impurity пня | $\frac{\lvert R_\ell \rvert}{\lvert R \rvert} H(R_\ell) + \frac{\lvert R_r \rvert}{\lvert R \rvert} H(R_r)$ |
| Критерий ветвления (Branch) | $\lvert R \rvert H(R) - \lvert R_\ell \rvert H(R_\ell) - \lvert R_r \rvert H(R_r)$ |
| Gain | $H(R) - H(R_\ell, R_r) = \text{Branch} / \lvert R \rvert$ |
| MSE impurity | $\frac{1}{\lvert R \rvert}\sum (y_i - \bar y_R)^2$ |
| MAE impurity | $\frac{1}{\lvert R \rvert}\sum \lvert y_i - \mathrm{median}(R) \rvert$ |
| Misclassification | $1 - \max_k p_k$ |
| Энтропия | $-\sum_k p_k \log_2 p_k$ (биты) |
| Джини | $1 - \sum_k p_k^2$ |
