## **Что дано в §2.3**

**Модель:** $y = w_0 + w_1 x$

- $w_1$ — наклон (разрешено учить на train)
- $w_0$ — сдвиг (запрещено учить на train)

**Правило:** $w_0$ **фиксирован**. Ты **не можешь** его обучать градиентным спуском.

**Что ты делаешь:** перебираешь $w_0 \in \{0,\ 0.1,\ 0.2,\ \ldots\}$ и **смотришь качество на test**.

---

## **Что кажется**

> «Я обучил модель с **одним** параметром ($w_1$). $w_0$ — это просто константа, которую я задал. Я его **не учил**.»

**Логика:** в коде нет строки

```python
w0 -= lr * grad
```

— ты **не оптимизировал** $w_0$ градиентом. Значит, он **не обучаемый**.

---

## **Что на самом деле**

**Ключевой вопрос:** *почему* ты выбрал именно это значение $w_0$?

**Ответ:** потому что оно дало **лучший результат на test**.

**А это значит:** информация из test **повлияла** на итоговое значение $w_0$. То есть $w_0$ **подстроился** под test.

> **Подбор значения по метрике = обучение этого значения по этой метрике.**

Не важно, **как** ты его настраиваешь:

- градиентным спуском (SGD);
- перебором вручную.

**Результат один:** значение **зависит** от данных, по которым ты его выбирал.

---

## **Конкретно: что происходит с $w_0$**

Представь, что **истинный** сдвиг — 2 (как в примере с квартирами). Ты перебираешь:

| **$w_0$ (сдвиг)** | **Test-ошибка** |
|----|----|
| 0 | 4.2 |
| 1 | 1.8 |
| **2** | **0.3** ← минимум |
| 3 | 1.5 |
| 4 | 3.9 |

Ты выбираешь $w_0 = 2$ — потому что **на test** он дал минимальную ошибку.

**Что произошло:**

- Ты **не учил** $w_0$ на train.
- Но ты **выбрал** $w_0$ по test.
- Значит, $w_0$ **зависит от test**.
- В итоге у тебя **два** параметра, подстроенных с участием test: $w_1$ (обучен на train, но зависит от $w_0$) и $w_0$ (выбран по test).

---

## **Почему «скрытый второй параметр»**

Слово **«скрытый»** — потому что формально ты **не считаешь** $w_0$ обучаемым:

- В коде нет обновления $w_0$ градиентом.
- Ты можешь честно сказать: «я обучил только $w_1$».

**Но фактически** $w_0$ — **обучаемый параметр**, просто «обучаешь» его **ты**, а не SGD. И «обучаешь» на **test**.

| **Что** | **Формально** | **Фактически** |
|----|----|----|
| $w_1$ | обучаемый | обучаемый |
| $w_0$ | «просто константа» | **обучаемый** (тобой, по test) |

> **«Скрытый параметр»** = параметр, который ты **не считаешь** обучаемым, но который **фактически подстроен под данные** (в данном случае — под test).

---

## **Аналогия: подбор пароля**

Тебе дали сейф и сказали:

> «Код подбирать нельзя. Можно **один раз** попробовать открыть.»

Ты такой: «Ок, не буду подбирать». Но потом:

- Попробовал `0000` — не открылся.
- Попробовал `0001` — не открылся.
- …
- Попробовал `1234` — **открылся!**

Ты **подобрал** код. Формально ты «не подбирал» — ты просто **пробовал**. Но **результат** тот же: ты **узнал** код из сейфа.

**С $w_0$ то же самое:** ты «не учил» его на test, ты «просто перебирал». Но **выбрал** то значение, которое **лучше всего подошло к test** → ты **узнал** $w_0$ из test.

---

## **Почему это важно для гиперпараметров**

Та же логика:

```text
Подбор гиперпараметра по test
    = «обучение» этого гиперпараметра на test
    = test больше не чистый
    = финальная оценка завышена
```

**Пример:** ты перебираешь `lr` и смотришь **test accuracy**:

| **lr** | **Test accuracy** |
|----|----|
| 1e-3 | 0.85 |
| **1e-4** | **0.91** ← выбрал |
| 1e-5 | 0.87 |

Ты выбрал `lr = 1e-4`, потому что он дал лучший **test**. Но теперь `lr` **зависит от test** → test «загрязнён» → цифра 0.91 **завышена** (это не честная оценка на новых данных, а **подгонка** под test).

**Правильно:** перебирать `lr` по **val**, а test трогать **один раз** в конце.

---

## **Почему «модель с двумя параметрами»**

Формально у тебя:

- $w_1$ — обучаемый (SGD на train);
- $w_0$ — фиксированный (ты его задаёшь).

**Но** итоговое значение $w_0$ **зависит от test**. Значит, **эффективно** у тебя **два** параметра, подстроенных с участием test:

$$
w_0 = f(\text{test}), \quad w_1 = g(\text{train},\ w_0)
$$

Оба в итоге **зависят от test** (через $w_0$).

**Степени свободы:** если ты перебрал **100** значений $w_0$, ты фактически добавил **100** «попыток» подогнаться под test. Это как если бы у модели было **100 дополнительных параметров**, каждый из которых ты настраивал по test.

> **Формулировка:** подбор **любой** настройки по test = **неявное обучение** на test. Даже если формально «обучаемых параметров» один.

---

## **Обобщение: что считается «обучением на test»**

| **Действие** | **Обучение на test?** |
|----|----|
| SGD обновляет $W$ по test-батчам | **Да**, явное |
| Ты перебираешь $w_0$ и выбираешь по test | **Да**, неявное |
| Ты перебираешь `lr` и выбираешь по test | **Да**, неявное |
| Ты перебираешь архитектуру и выбираешь по test | **Да**, неявное |
| Ты перебираешь признаки и выбираешь по test | **Да**, неявное |
| Ты смотришь на test **один раз** в конце | **Нет** — это финальная оценка |

**Правило:** **любое** решение, принятое на основе test, = обучение на test. Не важно, «учишь» ты параметр градиентом или «просто перебираешь».

---

## **Итог**

| **Что кажется** | **Что на самом деле** |
|----|----|
| Модель с **одним** обучаемым параметром $w_1$ | Модель с **двумя** параметрами, подстроенными с участием test |
| $w_0$ — «просто константа», не обучен | $w_0$ **выбран по test** → обучен на test (неявно) |
| Ты «не подбирал» $w_0$ | Ты **перебрал** значения и **выбрал лучшее по test** → подобрал |
| Test остался чистым | Test **загрязнён**: $w_0$ зависит от него |

> **Главная мысль:** подбор значения по метрике = обучение этого значения по этой метрике. Формально «не учил» — фактически **подогнал**. Поэтому гиперпараметры (и сдвиг) нельзя подбирать на test — иначе test перестаёт быть честной оценкой.
