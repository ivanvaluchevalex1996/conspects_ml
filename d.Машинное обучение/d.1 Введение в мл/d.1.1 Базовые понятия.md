# d.1.1 Базовые понятия

## 1. Суть обучения с учителем

Есть исторические пары **(признаки → правильный ответ)**. Модель смотрит на них, делает предсказание, получает штраф за ошибку и подкручивает настройки, чтобы следующий раз ошибаться меньше.

| На бытовом языке | В ML |
|:---|:---|
| Старые продажи / анкеты | Train dataset |
| Этаж, метраж, район | Признаки X |
| Цена / класс / диагноз | Целевая переменная Y |
| «Угадывание» моделью | Предсказание ŷ |
| Насколько далеко от правды | Loss → эмпирический риск |

**Одной фразой:** учимся на известных ответах, чтобы предсказывать ответы для новых объектов.

Проверка всегда на **отложенных** данных (модель их не видела при обучении). Иначе нельзя отличить «поняла закономерность» от «зазубрила таблицу».

## 2. Математическая запись данных

Невидимое правило природы: $y: X \to Y$. Мы его не знаем — хотим приблизить моделью $\hat y_\theta$.

$$
X_{\text{train}} \in \mathbb{R}^{n \times m},\qquad
y_{\text{train}} \in \mathbb{R}^{n}
\quad\text{(или метки / векторы — см. типы задач)}
$$

| Символ | Смысл |
|:---|:---|
| $n$ | Число объектов (строк) |
| $m$ | Число признаков (столбцов) |
| $X$ | Таблица признаков |
| $y$ | Столбец ответов |
| $x_{\text{new}}$ | Одна новая строка для прогноза |

## 3. Типы признаков

| Тип | Пример | Можно ли «складывать»? | Как подаём в модель |
|:---|:---|:---|:---|
| Числовые | площадь, км до метро | Да | Как есть (+ часто нормализация) |
| Категориальные | район, цвет | Нет | One-Hot → столбцы 0/1 |
| Порядковые | плохо / средне / хорошо | Сравнивать — да, умножать «как числа» — осторожно | Коды 1, 2, 3… с сохранением порядка |

Лайфхак: если осмысленно сказать «в 2 раза больше» — почти наверняка числовой признак.

## 4. Типы задач (по тому, что в Y)

| Задача | Что в Y | Пример |
|:---|:---|:---|
| Классификация | Одна метка из списка | Сорт ириса: 0/1/2 |
| Регрессия | Одно число | Цена дома |
| Многомерная регрессия | Несколько чисел сразу | Температура + влажность + давление |
| Multilabel | Несколько меток сразу (вектор 0/1) | Теги ресторана: итальянский + доставка |
| Ранжирование | Порядок в группе | Выдача поиска: кто выше кого |

Ключ: в классификации/регрессии ответ обычно **на объект**; в ранжировании важен **порядок группы**.

## 5. Параметрическое семейство моделей

Мы заранее выбираем *тип* формулы (прямая, пороги, дерево…), а внутри типа крутим **параметры** $\theta$.

$$
\mathbb{F} = \{\hat y_\theta \mid \theta \in \Theta\}
$$

| Символ | Смысл | Пример (аттракцион) |
|:---|:---|:---|
| $\mathbb{F}$ | Семейство («все такие правила») | Все пороги по росту и возрасту |
| $\theta$ | Настройки, которые учим | мин. рост $a$, мин. возраст $b$ |
| $\Theta$ | Допустимые значения настроек | $a \in [0,200]$, $b \in [0,18]$ |

Это **паспорт модели**, не формула для ручного подсчёта ответа. Ответ считаем уже после того, как нашли конкретное $\theta$.

У части методов параметров почти нет (KNN) — там крутят **гиперпараметры** вроде $k$.
