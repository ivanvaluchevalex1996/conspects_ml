## 0. Зачем (NLP / recsys в проде)

Большая модель **не влезает** в latency и бюджет:

| Требование | Приём |
| --- | --- |
| ранжирование на **каждый** запрос | маленькая модель, квантование, batch |
| эмбеддинги в реальном времени | DistilBERT, int8 Linear |
| LLM дешевле | дистилляция, квант (GPTQ/AWQ), прунинг |
| мобильный клиент | всё выше + ONNX/TensorRT |

Глава про **сжатие после** того, как качество достигнуто — типичный MLE/ML-инженерный собес.

---

## 1. Тройка приёмов

| Приём | Что режем | Типичный эффект |
| --- | --- | --- |
| **Квантование** | биты на вес (float32 → int8) | ~×4 меньше, быстрее CPU |
| **Прунинг** | веса ≈ 0 | разреженность, иногда структурный прунинг |
| **Дистилляция** | **архитектура** (ученик < учитель) | маленькая сеть с ~качеством большой |

Комбинируют: distill → quantize → deploy.

---

## 2. Квантование *(handbook 44.1)*

Веса обычно **float32** (4 байта). **int8** — 1 байт.

Аффинное отображение:

$$
\Large
q = \text{round}\!\left(\frac{x}{s}\right) + z, \qquad x \approx s\,(q - z)
$$

s — scale, z — zero-point.

| Вид | Суть |
| --- | --- |
| **Dynamic** | веса int8; активации на лету; проще всего (`quantize_dynamic` на Linear) |
| **Static PTQ** | калибровка активаций на выборке |
| **QAT** | «фейковый» quant при обучении — лучшее качество |

```python
import torch.ao.quantization as tq
quantized = tq.quantize_dynamic(model, {nn.Linear}, dtype=torch.qint8)
```

Для NLP много **Linear** — dynamic quant часто «первый кирпич».

---

## 3. Прунинг *(handbook 44.2)*

Многие веса **≈ 0** и не влияют.

| Тип | Что делают |
| --- | --- |
| **unstructured** | зануляют отдельные w (magnitude pruning) |
| **structured** | выкидывают целые каналы/нейроны — реальный выигрыш на железе |

```python
prune.l1_unstructured(layer, name="weight", amount=0.6)
```

После прунинга часто **дообучают** (fine-tune), иначе accuracy падает.

## 4. Дистилляция *(handbook 44.3)*

**Учитель** (большой) + **ученик** (малый). Ученик учится не только на **жёстких** метках y, но и на **мягком** распределении учителя — «тёмное знание» (7 похожа на 1 сильнее, чем на 8).

Температура T > 1 **размягчает** softmax:

$$
\Large
L = \alpha \cdot \text{CE}(\text{student}, y) + (1-\alpha) \cdot T^2 \cdot \text{KL}\big(\text{soft}_T(s) \,\|\, \text{soft}_T(t)\big)
$$

| Параметр | Роль |
| --- | --- |
| T | шире распределение, видны вторичные классы |
| α | баланс «метки» vs «учитель» |
| T² | компенсация градиента при делении на T |

**DistilBERT:** ~40% меньше, ~60% быстрее, ~97% качества BERT — эталонный пример для NLP.

## 5. Инференс без «потери смысла» *(handbook 44.4)*

| Приём | Зачем |
| --- | --- |
| `torch.compile`, ONNX, TensorRT | ускорить граф без смены математики |
| **fp16 / bf16** | память ↓, GPU быстрее |
| **LoRA** | не сжатие inference, но дешёвое дообучение |

Трейд-офф: после точки сжатия quality падает **обрывом** — на собесе говорят про **Pareto** качество/latency.

## 6. NLP / recsys сценарии

| Сценарий | Типичный стек |
| --- | --- |
| Классификатор текста на CPU | DistilBERT + dynamic quant |
| Ранжирование 1000 кандидатов | маленький двухбашенный MLP, fp16 |
| Онлайн-эмбеддинг | sentence-transformer small + batching |
| Чат (если не облако) | квантованный LLM, не полный fp32 |

---

## 7. Шпаргалка

- **Quant:** int8, scale/zero-point; dynamic — быстрый старт.
- **Prune:** занулить малые |w|; structured — для скорости.
- **Distill:** KL + temperature + маленький student.
- **Триаду комбинируют** перед продом.
