## 0. Зачем отдельная глава

Архитектуру понять легко; **сойдётся ли loss** — зависит от мелочей: нули в весах, lr без warmup, NaN от взрыва градиента. Глава 45 — **чек-лист инженера** при обучении трансформеров, глубоких MLP и RNN.

Для **fine-tune BERT/LLM** критичны: **малый lr**, **warmup**, **clip**, **LayerNorm** (не путать с BatchNorm).

---

## 1. Инициализация *(handbook 45.1)*

| Ошибка | Почему плохо |
| --- | --- |
| **все веса = 0** (или константа) | симметрия нейронов — одинаковые градиенты навсегда |
| **слишком большие** | активации и градиенты **взрываются** по слоям |
| **слишком маленькие** | **затухание** сигнала |

| Схема | Под что |
| --- | --- |
| **Xavier / Glorot** | tanh, sigmoid |
| **He / Kaiming** | **ReLU** (дефолт в современных CNN/MLP) |

He: дисперсия весов ∝ 2/n_in → std ≈ √(2/n_in).

```python
nn.init.kaiming_normal_(layer.weight, nonlinearity="relu")
nn.init.zeros_(layer.bias)
```

У `nn.Linear` в PyTorch уже разумный дефолт — **не обнуляй веса руками**.

Глубокий MLP без He — loss часто **не падает** (handbook: 10+ слоёв на digits).

## 2. Нормализации *(handbook 45.2)*

Нормируют активации: вычесть mean, поделить на std, затем обучаемые γ, β.

| Норма | Статистики по | Когда |
| --- | --- | --- |
| **BatchNorm** | батчу (per channel в CNN) | vision, большой batch |
| **LayerNorm** | признакам **одного** объекта | **трансформеры**, RNN |
| **GroupNorm** | группам каналов | малый batch, детекция |

```python
bn = nn.BatchNorm1d(64)(x)   # по батчу, per feature
ln = nn.LayerNorm(64)(x)     # per object, batch size не важен
```

**Правило:** CNN → BN; NLP/transformer → **LN**; train/eval для BN — [d.4.37](../../d.4%20Deep%20Learning/d.4.37%20Регуляризация%20в%20DL/d.4.37%20Регуляризация%20в%20DL.md).

## 3. Clip градиента *(handbook 45.3)*

В **RNN и трансформерах** норма градиента иногда **взрывается** → NaN.

```python
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
# затем optimizer.step()
```

Если после шага `loss=nan` — первые подозреваемые: **слишком большой lr** и отсутствие clip.

---

## 4. Warmup и lr *(handbook 45.4)*

В начале веса случайны — **большой lr** ломает модель. **Warmup:** первые шаги lr растёт от 0 до рабочего, потом cosine/step decay.

**Трансформеры без warmup** часто **не сходятся**. Fine-tune BERT: lr ~2e-5 + короткий warmup — стандарт.

Подробнее scheduler'ы — d.4.36 §2.6, pytorch/12.

## 5. Residual *(handbook 45.5)*

$$\Large y = F(x) + x$$

Не только ResNet: **блок трансформера** — attention + FFN с residual.

Градиент может «проехать» по **+x**, минуя затухание в F(x) → **сотни слоёв** обучаемы. Связь с [d.5.41](../d.5.41%20Свёрточные%20сети%20CNN/d.5.41%20Свёрточные%20сети%20CNN.md) (ResNet) и [d.5.40](../d.5.40%20Последовательности%20RNN%20LSTM%20GRU%20Transformer/d.5.40%20Последовательности%20RNN%20LSTM%20GRU%20Transformer.md).

## 6. Арсенал и отладка *(handbook 45.6)*

| Приём | Зачем |
| --- | --- |
| **AdamW** (weight decay) | веса не раздуваются |
| **label smoothing** | не переуверенность softmax |
| **AMP + grad accumulation** | память/скорость, большой эффективный batch |
| **seed** | воспроизводимость экспериментов |

### «Сеть не учится» — порядок проверки

1. **Learning rate** (чаще всего виноват).
2. **Данные и метки** (перепутаны классы, утечка).
3. **Масштаб входа** (нормализация).
4. **Инициализация**.
5. **NaN** → clip + уменьшить lr.

### Чек-лист handbook / собес

1. He для ReLU  
2. BN / **LN** по типу модели  
3. lr + **warmup** для трансформера  
4. **gradient clipping**  
5. **residual** для глубины  
6. нормализация **входных** признаков  

«90% проблем» — отсюда (формулировка ментора).

## 7. Связь с NLP / recsys

| Ситуация | Тонкость |
| --- | --- |
| Fine-tune классификатора текста | маленький lr, warmup, LN внутри BERT |
| Обучение two-tower с нуля | He/init, возможно BN на табличных фичах, LN на эмбеддинг-стеке |
| Длинные сессии (RNN/Transformer4Rec) | **clip** обязателен |
| Большой batch в ранжировании | grad accumulation |
