## 1. Инициализация весов *(спрашивают на собесах)*

**Нельзя** инициализировать все веса **нулём** / одной константой в многослойной сети: нейроны-«близнецы», градиенты не разводят их → обучение ломается.

**Идея нормальных схем:** сохранить разумный масштаб активаций и градиентов по слоям.

| Имя | Когда вспоминать |
| --- | --- |
| Xavier / Glorot | классика под tanh / sigmoid |
| **Kaiming / He** | под **ReLU** (твой обычный случай) |

**На практике:** в PyTorch у `nn.Linear` уже адекватный дефолт под ReLU. Главное — **не обнулять веса руками**.

На собесе: «Нули плохи из‑за симметрии; для ReLU берут Kaiming; во фреймворке часто уже так».

## 2. Градиентная оптимизация в DL *(лекция)*

### 2.1. Общая петля (как в классике)

```
батч → forward → loss → backward (autograd) → шаг оптимизатора по всем W, b
```

Один проход по (почти) всем данным = **эпоха**.

### 2.2. SGD

Обычный шаг:

$$
w \leftarrow w - \alpha \cdot \nabla_w L
$$

α — **learning rate**.  
Считают градиент не по всей выборке, а по **батчу** → стохастический GD.

Плюс: простой, предсказуемый.  
Минус: на сложных лоссах DL часто медленнее / капризнее Adam.

### 2.3. Momentum (идея в одну фразу)

Шаг «с инерцией»: не только текущий градиент, но и накопленное направление. Меньше дёрганья, быстрее по узким долинам. В чистом виде реже крутят руками — живёт внутри Adam.

### 2.4. Adam / AdamW — рабочий дефолт

**Adam** = адаптивный шаг по каждому параметру (учитывает «историю» градиентов).  
**AdamW** = Adam + корректный **weight decay** (регуляризация весов).

**Правило новичка / собеса:**

> Для большинства задач стартую с Adam или AdamW, lr порядка 1e-3, потом подстраиваю.

### 2.5. Learning rate scheduling *(пробел ментора — закрываем)*

Часто lr **уменьшают** по ходу обучения: сначала крупнее шаги, потом точная подстройка.

Типичные схемы (знать названия):

| Схема | Идея |
| --- | --- |
| StepLR | каждые N эпох умножить lr на 0.1 |
| ReduceLROnPlateau | лосс/метрика застряла → уменьшить lr |
| Cosine annealing | плавно снижать lr по «косинусе» |

На собесе: «lr schedule помогает дообучить, когда с фиксированным lr уже не ползёт».

### 2.6. Что сказать на собесе про оптимизацию

1. Учим градиентным спуском по батчам.  
2. SGD — база; на практике часто **Adam/AdamW**.  
3. Важен **learning rate**; часто используют **schedule**.  
4. Градиенты считает **autograd** (`loss.backward()`).

## 3. Регуляризация в DL *(лекция)*

**Регуляризация** = техники против переобучения (и иногда «навязать» модели желаемые свойства).

Три семьи (как в Яндексе):

### 3.1. Через лосс — weight decay

Штраф за большие веса ≈ L2 из классики.

Практика: `AdamW(..., weight_decay=1e-2)` (порядок подбирают).

### 3.2. Через структуру сети

#### Dropout

- на **train**: случайно обнуляет часть активаций;
- на **eval**: выключен, все нейроны работают;
- смысл: не зависеть от малого числа признаков → меньше переобучение;
- аналогия: как ансамбль многих «дырявых» подсетей.

PyTorch: `nn.Dropout(p=0.5)`, обязательно `model.train()` / `model.eval()`.

#### Batch Normalization (BatchNorm)

- нормирует активации **внутри батча** (среднее/дисперсия), потом учит свой масштаб;
- обучение обычно **быстрее и стабильнее**;
- позволяет брать больший lr;
- на train и eval ведёт себя по-разному (скользящая статистика на eval).

На собесе: «Dropout — против переобучения; BatchNorm — стабильность/скорость сходимости (плюс побочный регуляр.-эффект)».

### 3.3. Через данные — аугментации

Искусственно расширяем выборку: шум, поворот картинки, … без смены метки.

- must-have в **CV**;
- в таблицах — осторожно;
- преобразование должно быть **осмысленным** для задачи.

### 3.4. Early stopping (коротко)

Смотришь метрику на **валидации**; если долго не растёт — останавливаешь обучение. Классика против переобучения, в DL тоже используют.

### 3.5. Что сказать на собесе про регуляризацию

1. Weight decay / AdamW.  
2. Dropout (train vs eval).  
3. BatchNorm (зачем).  
4. Аугментации (особенно CV).  
5. Early stopping / смотреть train vs val.

## 4. Метрики и валидация в DL

В DL **те же** правила, что в классике: лосс — для обучения; метрика — для решения «модель хорошая или нет». Не путать.

Подробности метрик и CV уже есть у тебя — здесь только связка с нейросетями.

### 4.1. Сплиты

| Кусок | Зачем |
| --- | --- |
| train | крутим веса |
| validation | подбираем архитектуру / lr / early stopping; смотрим переобучение |
| test | финальная оценка **один раз** |

Сравнивай train vs val: train падает, val растёт → переобучение → dropout / weight decay / упростить сеть / early stopping.

Кросс-валидация в DL на больших данных часто дорогая; чаще фиксированный val. Идея та же — см. `d.3.2`.

### 4.2. Лосс ≠ метрика

| Задача | Чем учим (лосс) | Чем оцениваем (метрика) |
| --- | --- | --- |
| бинарная | log loss | accuracy, precision/recall, F1, ROC-AUC |
| много классов | cross-entropy | accuracy, macro-F1, … |
| регрессия | MSE / MAE | MAE, RMSE, R² |

Формулы и когда какую метрику брать → `d.3.1` (и `d2.2` / вероятности в `d.3.6` при необходимости).

### 4.3. Как это выглядит в цикле обучения

```
каждая эпоха:
  model.train()  → прогон train → средний train loss
  model.eval()   → прогон val  → val loss + метрики (без dropout-шума)
если val метрика давно не растёт → early stopping (или уменьшить lr)
в конце → один раз test
```

На собесе: «Учу по лоссу, качество смотрю метриками на val; test не трогаю до финала».
