*(Разбор с нуля: зачем выключать нейроны, если DL как раз нужен ради скрытых признаков; чем Dropout отличается от «выключения» через ReLU; пример на трёх нейронах. Теория → [`d.4.3` §2.2](d.4.3%20Регуляризация%20в%20Deep%20Learning.md). ReLU и скрытые признаки → [`d.4.1`](../d.4.1%20Полносвязные%20нейронные%20сети.md).)*

## 0. Зачем этот файл

Частый вопрос: DL нужен, чтобы сеть **сама** делала скрытые признаки (то, что в классике делали руками). Зачем тогда Dropout их «выкидывает»?

Ответ коротко: **не выкидывает насовсем**. Выключает случайные нейроны только на одном шаге обучения, чтобы сеть не повесила всё на один-два нейрона. На тесте работают все.

---

## 1. Две разные «выключки» — не путать

| | ReLU | Dropout |
| --- | --- | --- |
| когда нейрон даёт 0 | если z < 0 → h = 0 | случайно, даже если h был полезный |
| зачем | нелинейность (часть формулы нейрона) | чтобы другие нейроны тоже учились |
| на train | работает | работает |
| на test | работает так же | **выключен**: никто случайно не гасится |

ReLU — часть самого нейрона:

$$
\Large
h = \mathrm{ReLU}(z) = \max(0, z)
$$

Dropout — «тренерский приём» на время учёбы. На экзамене (test) его нет.

---

## 2. Пример: 3 скрытых нейрона → цена

После ReLU на одном объекте:

| нейрон | z | h = ReLU(z) |
| --- | --- | --- |
| A | 2.0 | **2.0** |
| B | −1.0 | **0** ← ReLU сам выключил |
| C | 1.5 | **1.5** |

B «молчит» не из‑за Dropout, а потому что z отрицательный. Это нормально для ReLU: на другом объекте у B может быть z > 0.

Выходной слой (bias не пишем):

$$
\Large
\hat{y} = 3 \cdot h_A + 1 \cdot h_B + 2 \cdot h_C
$$

---

## 3. Без Dropout

На train почти всегда работают A и C. Сеть быстро вешает всё на A:

- вес у A становится огромным;
- C почти не нужен;
- B и так часто 0.

На train ŷ отличный. На новом объекте A чуть другой → предсказание разваливается, а C «не натренирован» подстраховать. Это и есть переобучение.

---

## 4. С Dropout (p = 0.5)

p — вероятность **выключить** нейрон на этом шаге. Маска на каждом шаге новая.

**Шаг 1.** Выключили A. После ReLU было (2, 0, 1.5), после Dropout: **(0, 0, 1.5)**.

Считает только C. Ошибка большая → градиент идёт в C (и в веса до него). C **вынужден** учиться предсказывать без A.

**Шаг 2.** Выключили C: **(2, 0, 0)**. Учится в основном A.

**Шаг 3.** Выключили B (он и так 0) — почти как обычно, учатся A и C вместе.

Через много шагов и A, и C умеют что-то полезное. На **test** Dropout выключен → A и C работают вместе → устойчивее.

**Важно понять:** на тесте Dropout **всегда выключен** (`model.eval()`), чтобы все нейроны могли работать. Но нейрон B на этом объекте всё равно будет 0 — не из‑за Dropout, а потому что z = −1 и ReLU дал h = 0. На другом объекте у B может быть z > 0, и тогда B тоже участвует в ŷ. Случайных «дыр» на тесте нет; нули из‑за ReLU — как обычно.

> Аналогия: ты не увольняешь сотрудников. На тренировке иногда убираешь «звезду», чтобы остальные тоже умели играть. На матче (test) все на поле — но если у кого-то сегодня «нет сигнала» (ReLU → 0), он просто не бьёт по мячу на этой атаке.

Масштаб: выжившие на train умножают на 1/(1−p), чтобы средний сигнал на train и test совпадал (inverted dropout). Разобрано в [`d.4.3` §2.2](d.4.3%20Регуляризация%20в%20Deep%20Learning.md); в PyTorch уже внутри `nn.Dropout`.

---

## 5. «Раз все учатся — предсказание точнее?»

Точнее на **новых** данных, а не на train:

| | без Dropout | с Dropout |
| --- | --- | --- |
| train | часто лучше (сеть может зазубрить) | обычно чуть хуже: на каждом шаге работает «дырявая» сеть |
| val / test | может быть хуже (зазубрила) | обычно лучше: признаки устойчивее |

Цель Dropout — не максимум на train, а чтобы модель лучше работала на данных, которых не видела.

Это не гарантия. Слишком большой p (например, 0.9) — сеть почти не может учиться, качество падает везде. Обычно p ≈ 0.1–0.5, подбирают по val.

## 6. Сводка

| вопрос | ответ |
| --- | --- |
| выкидываем признаки насовсем? | нет, только на одном шаге train |
| чем отличается от ReLU = 0? | ReLU — по формуле (z < 0); Dropout — случайно, специально |
| что даёт | признаки распределены по сети, меньше переобучение |
| что на test | Dropout выключен (`model.eval()`); но ReLU по-прежнему может дать h = 0, если z < 0 |
| чем не L2 | L2 — штраф в лоссе; Dropout — через структуру сети |

**На собесе:** «Dropout на обучении случайно выключает нейроны, чтобы сеть не полагалась на пару признаков; на тесте все включены — `model.eval()`.»
